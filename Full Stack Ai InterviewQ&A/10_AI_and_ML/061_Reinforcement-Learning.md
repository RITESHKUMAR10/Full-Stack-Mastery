# 🟢 Part 1: Fresher (0–1 year)

### Q1. What is reinforcement learning? *(Must-know)*
RL is a way of learning to **make sequences of decisions by interacting with an environment**. An agent observes a state, takes an action, receives a reward and a new state, and learns a **policy** that maximises cumulative (discounted) reward. There is no labelled "correct action"; the signal is delayed, sparse and evaluative.

### Q2. RL vs supervised vs unsupervised learning *(Must-know)*
| Aspect | Supervised | Unsupervised | Reinforcement |
|---|---|---|---|
| Feedback | Correct label per example | None | Scalar reward (often delayed) |
| Data | Fixed i.i.d. dataset | Fixed dataset | Generated by the agent's own actions |
| Goal | Predict labels | Find structure | Maximise long-term return |
| Key issue | Generalisation | Evaluation | Exploration, credit assignment, stability |

### Q3. Core RL terminology *(Must-know)*
- **Agent**: the learner/decision-maker. **Environment**: everything it interacts with.
- **State `s`**: description of the situation (or **observation** if partial).
- **Action `a`**: a choice the agent makes. **Reward `r`**: scalar feedback.
- **Policy `π(a|s)`**: behaviour; maps states to actions (deterministic or stochastic).
- **Return `G_t = r_{t+1} + γ r_{t+2} + …`**: discounted sum of future rewards.
- **Value `V^π(s)`**: expected return from `s` following `π`. **Action-value `Q^π(s,a)`**: expected return after taking `a` in `s`, then following `π`.
- **Episode**: one run from start to terminal state.

### Q4. Discount factor γ
`γ ∈ [0,1]` weights future rewards. `γ=0` is myopic; `γ→1` is far-sighted. It also keeps infinite-horizon returns finite and encodes preference for sooner rewards. Typical values: 0.95–0.999.

### Q5. Markov Decision Process (MDP) *(Must-know)*
A tuple `(S, A, P, R, γ)`: states, actions, transition probabilities `P(s'|s,a)`, reward function `R(s,a,s')`, discount. The **Markov property**: the future depends only on the current state and action, not on history.

### Q6. Exploration vs exploitation *(Must-know)*
Exploit what you know gives high reward; explore to discover potentially better actions. Too little exploration → stuck in suboptimal behaviour; too much → wasted reward. Methods: ε-greedy, softmax/Boltzmann, UCB, Thompson sampling, entropy bonuses, curiosity.

### Q7. ε-greedy
With probability ε take a random action, otherwise the greedy action `argmax_a Q(s,a)`. ε is usually decayed over time (e.g., 1.0 → 0.05).

### Q8. Bellman expectation equation
`V^π(s) = Σ_a π(a|s) Σ_{s'} P(s'|s,a)[R + γ V^π(s')]`. Value of a state = expected immediate reward plus discounted value of the next state. The recursive structure powers almost every RL algorithm.

### Q9. Bellman optimality equation
`Q*(s,a) = Σ_{s'} P(s'|s,a)[R + γ max_{a'} Q*(s',a')]`. The optimal policy acts greedily with respect to `Q*`.

### Q10. Q-learning *(Must-know)*
Off-policy temporal-difference control:
`Q(s,a) ← Q(s,a) + α [ r + γ max_{a'} Q(s',a') − Q(s,a) ]`
It learns `Q*` regardless of the behaviour policy (as long as all state-action pairs are visited enough and α decays suitably).

### Q11. SARSA
On-policy TD control: `Q(s,a) ← Q(s,a) + α [ r + γ Q(s',a') − Q(s,a) ]`, where `a'` is the action actually taken by the current (e.g., ε-greedy) policy. It accounts for exploration risk, so it learns "safer" paths than Q-learning (the classic cliff-walking example).

### Q12. On-policy vs off-policy *(Must-know)*
On-policy: learns the value of the policy used to generate data (SARSA, A2C, PPO). Off-policy: learns about a target policy from data produced by a different behaviour policy (Q-learning, DQN, SAC); enables replay buffers and learning from logs, but is less stable.

### Q13. Model-free vs model-based
Model-free methods learn policy/value directly from experience. Model-based methods learn or use a model of dynamics `P` and `R` for planning (Dyna, MuZero, Dreamer). Model-based is more sample-efficient when the model is accurate.

### Q14. Temporal-difference (TD) learning
Updates estimates from other estimates (**bootstrapping**): `V(s) ← V(s) + α[r + γV(s') − V(s)]`. Lower variance than Monte Carlo, can learn online and in continuing tasks, but biased by initial estimates.

### Q15. Monte Carlo methods
Learn from complete episodes using actual returns `G_t`. Unbiased but high variance, require episodic tasks, and update only at episode end.

### Q16. Dynamic programming (DP)
When the model is known: **policy evaluation**, **policy iteration** (evaluate → improve), **value iteration** (apply the Bellman optimality backup repeatedly). Needs a full model and is expensive for large state spaces.

### Q17. Tabular vs function approximation
Tabular methods store a value per state(-action): fine for small discrete problems. Large/continuous spaces need function approximation (linear features, neural networks) to generalise.

### Q18. Deep Q-Network (DQN) *(Must-know)*
Q-learning with a neural network. Two key stabilisers: **experience replay** (random minibatches from a buffer break correlation) and a **target network** (periodically copied weights give a stable regression target). Loss: `(r + γ max_a' Q_target(s',a') − Q(s,a))²`.

### Q19. Experience replay
Store transitions `(s,a,r,s',done)` in a buffer and sample random minibatches. Improves sample efficiency and decorrelates updates; valid for off-policy methods only.

### Q20. Policy gradient (intro)
Directly optimise a parameterised policy `π_θ` by gradient ascent on expected return: `∇J(θ) = E[ ∇ log π_θ(a|s) · G_t ]` (REINFORCE). Works with continuous actions and stochastic policies.

### Q21. Actor-critic
The **actor** is the policy; the **critic** estimates value and provides a lower-variance learning signal (advantage). Combines the strengths of policy gradients and value-based learning (A2C, PPO, SAC).

### Q22. Advantage function
`A(s,a) = Q(s,a) − V(s)`: how much better an action is than average in that state. Subtracting the baseline `V(s)` reduces variance without introducing bias.

### Q23. Reward shaping and sparse rewards
Sparse rewards (only at success) make learning slow. Shaping adds intermediate rewards, but badly designed shaping creates **reward hacking**. Potential-based shaping `F = γΦ(s') − Φ(s)` preserves the optimal policy.

### Q24. Gymnasium basics
```python
import gymnasium as gym
env = gym.make("CartPole-v1")
obs, info = env.reset(seed=0)
done = False
while not done:
    action = env.action_space.sample()
    obs, reward, terminated, truncated, info = env.step(action)
    done = terminated or truncated
```
`terminated` = reached a true terminal state; `truncated` = time limit/cut-off.

### Q25. Tiny tabular Q-learning
```python
import numpy as np, gymnasium as gym
env = gym.make("FrozenLake-v1", is_slippery=False)
Q = np.zeros((env.observation_space.n, env.action_space.n))
alpha, gamma, eps = 0.1, 0.99, 1.0
for ep in range(5000):
    s, _ = env.reset(); done = False
    while not done:
        a = env.action_space.sample() if np.random.rand() < eps else int(Q[s].argmax())
        s2, r, term, trunc, _ = env.step(a); done = term or trunc
        Q[s, a] += alpha * (r + gamma * (0 if term else Q[s2].max()) - Q[s, a])
        s = s2
    eps = max(0.05, eps * 0.999)
```
Note the bootstrap target is zeroed only on **termination**, not truncation.

### Q26. Typical RL applications
Games (Atari, Go, StarCraft), robotics and control, recommender systems and ads, resource allocation (data-centre cooling, scheduling), finance/trading (with caution), chip design, healthcare dosing research, autonomous driving components, and **LLM post-training** (RLHF).

### Q27. Why is RL hard? *(Must-know)*
Sample inefficiency, sparse/delayed rewards (credit assignment), non-stationary data distribution, exploration, instability (bootstrapping + off-policy + function approximation: "deadly triad"), sensitivity to hyper-parameters and seeds, and reward design.

### Q28. Episodic vs continuing tasks
Episodic tasks end in a terminal state (game). Continuing tasks run indefinitely (process control); they need discounting or the average-reward formulation.

### Q29. Deterministic vs stochastic policy
Deterministic: `a = μ(s)`. Stochastic: sample `a ~ π(·|s)`. Stochastic policies help exploration, partially observable settings and games requiring mixed strategies.

### Q30. Common RL libraries
Gymnasium (environments), Stable-Baselines3 (reliable algorithm implementations), CleanRL (single-file references), RLlib (distributed), TRL (LLM RL), PettingZoo (multi-agent), MuJoCo/Isaac/Brax (physics simulators).

# 🔵 Part 2: Junior (1–3 years)

### Q31. The deadly triad *(Must-know)*
Function approximation + bootstrapping + off-policy learning together can cause divergence. DQN mitigates with target networks, replay and clipping; analysis tools include gradient clipping, smaller LR, and double-Q methods.

### Q32. DQN improvements (Rainbow components)
- **Double DQN**: decouple action selection (online net) and evaluation (target net) to reduce overestimation.
- **Dueling networks**: separate `V(s)` and advantage streams.
- **Prioritized replay**: sample high-TD-error transitions more.
- **Multi-step returns (n-step)**: faster credit propagation.
- **Distributional RL (C51, QR-DQN)**: learn the return distribution.
- **Noisy nets**: learned exploration.

### Q33. Overestimation bias in Q-learning
Taking `max` over noisy estimates is positively biased. Double Q-learning/Double DQN and TD3's clipped double-Q reduce it.

### Q34. Target network update styles
Hard update every `C` steps, or **soft (Polyak) update** `θ' ← τθ + (1−τ)θ'` with small τ (0.005). Soft updates are standard in DDPG/TD3/SAC.

### Q35. REINFORCE and variance reduction
`∇J = E[ Σ_t ∇ log π(a_t|s_t) (G_t − b(s_t)) ]`. Use a baseline (value function), reward-to-go instead of total return, normalisation of returns/advantages, and larger batches.

### Q36. Generalized Advantage Estimation (GAE) *(Must-know)*
`A_t^{GAE(γ,λ)} = Σ_l (γλ)^l δ_{t+l}`, where `δ_t = r_t + γV(s_{t+1}) − V(s_t)`. λ trades bias (λ→0) vs variance (λ→1); typical λ=0.95.

### Q37. A2C / A3C
Advantage Actor-Critic runs multiple environment copies and updates with n-step advantages. A3C is the asynchronous variant; A2C is synchronous and GPU-friendly.

### Q38. PPO (Proximal Policy Optimization) *(Must-know)*
Maximises a **clipped surrogate objective**: `L = E[ min( r_t(θ) A_t , clip(r_t(θ), 1−ε, 1+ε) A_t ) ]` with `r_t = π_θ(a|s)/π_old(a|s)`. The clip prevents destructive large policy updates, allowing multiple epochs on the same batch. Simple, robust and widely used (control, games, RLHF).

### Q39. TRPO vs PPO
TRPO enforces a KL-divergence trust region with second-order optimisation (conjugate gradient); PPO approximates it with clipping or a KL penalty and is far simpler and faster.

### Q40. PPO hyper-parameters
`clip_range` (0.1–0.3), `n_steps`/batch size, number of epochs (3–10), minibatches, `gae_lambda`, `gamma`, learning rate (3e-4), entropy coefficient (0–0.01), value-loss coefficient, gradient clipping (0.5), advantage normalisation.

### Q41. Continuous action spaces
Policies output a distribution (e.g., Gaussian with mean and log-std, then squashed with tanh). Value-based DQN can't handle them directly, so use actor-critic methods (DDPG, TD3, SAC, PPO).

### Q42. DDPG
Deterministic actor + Q critic, off-policy with replay and target networks; adds exploration noise (Gaussian/OU). Sensitive and brittle; TD3 and SAC are generally preferred.

### Q43. TD3
Twin Delayed DDPG: **two critics** (take the min), **delayed actor updates**, and **target policy smoothing** noise. Fixes DDPG's overestimation and instability.

### Q44. SAC (Soft Actor-Critic) *(Must-know)*
Off-policy maximum-entropy actor-critic: maximises return **plus entropy** `J = E[Σ r + α H(π)]`, encouraging exploration and robustness. Uses twin critics and (usually) auto-tuned temperature α. A strong default for continuous control.

### Q45. Entropy regularisation
Adding an entropy bonus discourages premature collapse to deterministic behaviour and aids exploration; the coefficient is often annealed or auto-tuned.

### Q46. Observation and reward normalisation
Normalise observations (running mean/std) and scale rewards or returns; essential for PPO on many tasks. Save normalisation statistics with the model for evaluation/deployment.

### Q47. Frame stacking and recurrent policies
Single frames don't reveal velocity (Atari). Stack frames or use RNN/LSTM/Transformer policies for partial observability (POMDPs).

### Q48. Partially observable MDPs (POMDPs)
The agent receives observations, not full states. Solutions: memory (RNN/attention), belief states, frame stacking, or recurrent critics.

### Q49. Vectorised environments
Run many env copies in parallel (`gym.vector`, SB3 `VecEnv`, EnvPool) for throughput and decorrelated data; watch for auto-reset semantics and final-observation handling.

### Q50. Evaluation protocol *(Must-know)*
Evaluate with a separate env, deterministic policy (or mean action), many episodes, multiple **random seeds**, and report mean ± std/confidence intervals or interquartile mean. Learning curves from single seeds are misleading.

### Q51. Reproducibility pitfalls
Seeds for NumPy/torch/env/action-space, non-determinism in simulators and GPUs, library versions, normalisation stats, and hyper-parameter tuning on the same seeds you report. Log config + git SHA.

### Q52. Hyper-parameter sensitivity
RL is sensitive to learning rate, batch size, γ, entropy and network size. Use sensible defaults from papers/libraries (SB3 zoo), tune with Optuna on multiple seeds, and prefer robust algorithms (PPO/SAC).

### Q53. Multi-armed bandits *(Must-know)*
A single-state RL problem: choose arms to maximise reward. Strategies: ε-greedy, **UCB** (`μ + c√(ln t / n)`), **Thompson sampling** (sample from posterior). Regret measures the cost of not always choosing the best arm.

### Q54. Contextual bandits
Choose actions based on context features (user, time) without long-term state transitions: LinUCB, neural bandits. Common in recommendations and ads; much simpler and safer than full RL when actions don't affect future states.

### Q55. When to use bandits instead of RL
If decisions are independent, feedback is immediate and actions don't change future context, use bandits (or A/B tests). Full RL is for sequential decisions with delayed, state-dependent consequences.

### Q56. Imitation learning basics
Learn from expert demonstrations. **Behaviour cloning** is supervised learning on `(s, a)` pairs, but suffers **compounding errors** (distribution shift). **DAgger** queries the expert on states visited by the learner.

### Q57. Inverse RL
Infer the reward function that explains expert behaviour (MaxEnt IRL, GAIL). Useful when rewards are hard to specify, but ambiguous and expensive.

### Q58. Reward hacking / specification gaming *(Must-know)*
The agent exploits loopholes in the reward (spinning in circles for points, exploiting simulator bugs). Mitigate by careful reward design, constraints, adversarial evaluation, human oversight and multi-objective checks.

### Q59. Simulators and environments
Gymnasium classic control, Atari (ALE), MuJoCo, PyBullet, Isaac Gym/Lab, Brax (JAX), DeepMind Control Suite, Unity ML-Agents, CARLA (driving), custom business simulators. A high-quality simulator is often the biggest enabler.

### Q60. Writing a custom Gymnasium env
```python
import gymnasium as gym, numpy as np
from gymnasium import spaces

class InventoryEnv(gym.Env):
    def __init__(self):
        self.observation_space = spaces.Box(0, 100, shape=(1,), dtype=np.float32)
        self.action_space = spaces.Discrete(21)           # order 0..20 units
    def reset(self, seed=None, options=None):
        super().reset(seed=seed); self.stock, self.t = 20, 0
        return np.array([self.stock], np.float32), {}
    def step(self, a):
        demand = self.np_random.poisson(8)
        sold = min(self.stock + a, demand)
        self.stock = min(100, self.stock + a - sold)
        reward = 5 * sold - 1 * self.stock - 2 * a
        self.t += 1
        return np.array([self.stock], np.float32), float(reward), False, self.t >= 50, {}
```

# 🟡 Part 3: Mid (3–5 years)

### Q61. Policy gradient theorem
`∇_θ J(θ) = E_{s~d^π, a~π}[ ∇_θ log π_θ(a|s) · Q^π(s,a) ]`. It gives a gradient without differentiating the state distribution, enabling sample-based estimates. Subtracting any baseline `b(s)` keeps it unbiased.

### Q62. Importance sampling in RL
Reweights data from a behaviour policy `μ` to estimate returns under `π`: ratio `π(a|s)/μ(a|s)`. High variance for long horizons; truncation (Retrace, V-trace, IMPALA) stabilises off-policy corrections. PPO's ratio is a one-step importance weight.

### Q63. IMPALA / distributed RL
Many actors generate trajectories; a central learner updates the policy asynchronously with V-trace correction for policy lag. Others: Ape-X (distributed prioritised replay), R2D2 (recurrent replay), SEED RL, Sample Factory for high throughput.

### Q64. Model-based RL approaches
- **Dyna**: mix real and model-generated data.
- **MBPO**: short model rollouts to augment replay.
- **PETS / MPC**: plan online with an ensemble dynamics model.
- **Dreamer**: learn a latent world model and train policies in imagination.
- **MuZero**: learn a value-equivalent model and plan with MCTS.
Issue: model bias compounds with horizon; use ensembles, short rollouts, uncertainty estimates.

### Q65. Monte Carlo Tree Search (MCTS)
Build a search tree by repeated selection (UCT), expansion, simulation/evaluation and backup. AlphaGo/AlphaZero combine MCTS with policy/value networks for superhuman play.

### Q66. Offline (batch) RL *(Must-know)*
Learn from a fixed dataset without environment interaction (logged data). Challenge: **distribution shift / extrapolation error**, because Q-values for unseen actions are overestimated. Methods: BCQ, **CQL** (conservative Q), IQL (in-sample), TD3+BC, Decision Transformer (sequence modelling). Evaluate with off-policy estimation (IS, doubly robust, FQE) and careful online validation.

### Q67. Off-policy evaluation (OPE)
Estimate a new policy's value from logged data: importance sampling, weighted IS, doubly-robust, fitted Q evaluation (FQE). Variance and coverage (support overlap) are the main concerns; always validate with small online tests.

### Q68. Exploration techniques beyond ε-greedy
Count-based/pseudo-counts, curiosity (ICM), Random Network Distillation (RND), Go-Explore, parameter-space noise, Thompson-style ensembles (bootstrapped DQN), entropy maximisation. Needed for sparse-reward, hard-exploration problems (Montezuma's Revenge).

### Q69. Hierarchical RL
Decompose tasks into temporally extended actions: options framework, feudal networks, goal-conditioned policies with subgoals (HIRO). Helps long-horizon tasks and transfer; adds design complexity.

### Q70. Goal-conditioned RL and HER
Policy conditioned on a goal `π(a|s,g)`. **Hindsight Experience Replay** relabels failed trajectories with achieved goals as if they were intended, turning sparse failures into learning signal (robot manipulation).

### Q71. Curriculum learning
Gradually increase task difficulty (start positions, goal distance, opponent strength) or automatically generate tasks (self-play, domain randomisation scheduling). Reduces exploration burden.

### Q72. Self-play
Agents train against copies/past versions of themselves (AlphaZero, OpenAI Five). Provides adaptive difficulty; risks cycling and forgetting, mitigated by opponent pools and league training.

### Q73. Multi-agent RL (MARL) *(Must-know)*
Multiple learning agents share an environment: cooperative, competitive or mixed. Challenges: non-stationarity (others change), credit assignment, scalability, partial observability. Paradigms: independent learners, **centralised training with decentralised execution (CTDE)** — MADDPG, QMIX, MAPPO.

### Q74. Game theory links
Nash equilibrium, zero-sum vs general-sum games, regret minimisation (CFR for poker), population-based training. Equilibrium is not always desirable or unique.

### Q75. Safe RL and constrained MDPs
Maximise reward subject to cost constraints (CMDP): Lagrangian methods (PPO-Lagrangian), CPO, shielding, safe exploration with barrier functions, risk-sensitive objectives (CVaR). Essential for physical systems and finance.

### Q76. Robustness and domain randomisation
Randomise physics, visuals and dynamics in simulation so the policy generalises to the real world (OpenAI's Rubik's cube). Also adversarial perturbations and robust RL objectives.

### Q77. Sim-to-real transfer
Gap from imperfect simulation. Techniques: domain randomisation, system identification, residual policies, fine-tuning on real data, domain adaptation, high-fidelity sensors/actuator models, and safety layers.

### Q78. Reward design best practices
Align with true objective, keep rewards bounded and scaled, avoid unintended shortcuts, combine terms with explicit weights, test with scripted/adversarial policies, log individual reward components, and consider learned rewards from human feedback when objectives are fuzzy.

### Q79. Credit assignment
Determining which past actions caused a delayed reward. Tools: discounting, eligibility traces (TD(λ)), n-step returns, GAE, attention/return decomposition (RUDDER), hindsight methods.

### Q80. Eligibility traces & TD(λ)
Blend n-step returns with weight λ; traces propagate TD errors to recently visited states. λ=0 is one-step TD, λ=1 is Monte Carlo.

### Q81. Distributional RL
Model the full return distribution `Z(s,a)` instead of its mean (C51, QR-DQN, IQN). Improves learning signal, enables risk-sensitive policies.

### Q82. Network architecture choices
MLPs for low-dim states, CNNs for pixels (Nature-CNN, IMPALA ResNet), LSTMs/Transformers for memory, layer norm and orthogonal init for stability, shared vs separate actor/critic networks (separate often better for continuous control).

### Q83. Training diagnostics *(Must-know)*
Monitor episodic return, episode length, value loss, policy loss, entropy, KL divergence to old policy, clip fraction, explained variance of the critic, gradient norms, and learning rate. Collapsing entropy, KL spikes or explained variance near 0 reveal issues.

### Q84. Frame-skip, action repeat and time limits
Action repeat (4 in Atari) reduces effective horizon. Treat time-limit **truncation** correctly (bootstrap from the next state value), and expose time as input if the policy needs it.

### Q85. Sample efficiency strategies
Off-policy replay, high update-to-data ratio (REDQ, DroQ), data augmentation for pixels (DrQ, RAD), model-based methods, pre-training with offline data/demonstrations, auxiliary self-supervised losses (CURL).

### Q86. Imitation + RL fine-tuning
Pre-train with behaviour cloning on demonstrations, then fine-tune with RL (with KL regularisation to the demonstration policy) to avoid starting from scratch and to avoid dangerous exploration.

### Q87. Transformers in RL
Decision Transformer treats RL as sequence modelling conditioned on desired return; Gato-style generalist agents; Transformers as memory in POMDPs. Strong for offline data; weaker at stitching suboptimal trajectories without care.

### Q88. Recommendation as RL
Slate/sequence recommendation with long-term engagement as return. Practical issues: huge action spaces (embedding-based policies), off-policy logged data with selection bias, delayed/sparse feedback, safe rollout. Many teams start with contextual bandits and add long-horizon value later.

### Q89. Resource allocation / operations RL
Examples: dynamic pricing, inventory, cluster scheduling, energy management. Build a faithful simulator or digital twin, constrain actions with business rules, compare to strong baselines (heuristics, MPC, OR solvers), and deploy gradually with fallbacks.

### Q90. Baselines you must beat
Random, scripted/heuristic policy, supervised/behaviour-cloned policy, operations-research solvers, and a simple bandit. Many "RL wins" vanish against a tuned heuristic.

# 🟠 Part 4: Senior (5–7 years)

### Q91. RLHF pipeline for LLMs *(Must-know)*
1. Supervised fine-tuning (SFT) on demonstrations.
2. Collect human preference comparisons between model responses; train a **reward model** (Bradley–Terry loss).
3. Optimise the policy with RL (PPO) to maximise reward, with a **KL penalty** to the SFT/reference model to prevent drift and reward hacking.
4. Evaluate, red-team and iterate.
See `../11_Generative_AI/066_LLM-and-RAG.md` and `../11_Generative_AI/076_AI-Safety-and-Responsible-AI.md`.

### Q92. DPO and other preference-optimisation methods
**Direct Preference Optimisation** skips the explicit reward model and RL loop: it optimises a classification-style loss on chosen vs rejected responses relative to a reference model: `−log σ(β[(log π(y_w|x) − log π_ref(y_w|x)) − (log π(y_l|x) − log π_ref(y_l|x))])`. Simpler and more stable; related methods: IPO, KTO, ORPO, SimPO. Still sensitive to data quality and β.

### Q93. GRPO and RL with verifiable rewards
Group Relative Policy Optimisation samples a group of responses per prompt and uses group-normalised rewards as advantages (no learned value network). Combined with **verifiable rewards** (unit tests, math answer checking), it trains reasoning behaviour in LLMs. Risks: reward hacking, length inflation, format gaming; require careful reward checks and held-out evaluation. Verify details in current papers/TRL docs.

### Q94. RLAIF and Constitutional approaches
Use AI feedback (guided by written principles) in place of or in addition to human preference labels to scale alignment data. Quality depends on the judge model and principles; audit with human samples.

### Q95. Reward model failure modes
Over-optimisation (Goodhart's law): policy exploits reward-model errors, producing verbose, sycophantic or off-distribution outputs. Mitigations: KL control, reward-model ensembles, early stopping by gold-standard eval, regularisation, periodic refresh with new human data, length normalisation.

### Q96. Credit assignment in language generation
Reward often arrives at the end of a response (sequence-level), though actions are tokens. Options: sequence-level advantages (GRPO/RLOO), process reward models (step-level), token-level KL, value heads. Bandit-style formulation is common (single-step per prompt).

### Q97. Stabilising PPO for large models
Whitening advantages, smaller LR, clip ratio, KL controller, value-head warm-up, separate or shared backbone trade-offs, gradient accumulation, reward clipping/normalisation, generation hyper-parameters fixed during training, and careful mixed-precision handling.

### Q98. Off-policy vs on-policy at scale
On-policy methods (PPO) are simple and stable but sample-hungry; off-policy (SAC, Q-learning with replay) is more sample-efficient but trickier. With cheap simulators (Brax, Isaac) massively parallel on-policy training wins on wall-clock; with expensive real-world data prefer off-policy/offline.

### Q99. GPU-accelerated simulation
Brax, Isaac Lab, MJX (MuJoCo in JAX), ManiSkill run thousands of environments on GPU, cutting training from days to minutes. Requires batching-friendly physics and care with domain gaps and reset logic.

### Q100. Robustness testing of policies
Test against perturbations (sensor noise, delays, friction), rare events, adversarial opponents, distribution shifts, and failure injection. Use scenario suites and statistical guarantees (many seeds, confidence bounds), not single rollouts.

### Q101. Safe deployment of RL policies
Shadow mode → human-in-the-loop → constrained action sets → gradual traffic ramp → automatic fallback to baseline policy on anomalies. Monitor reward, constraint violations, state/action distributions, and OOD detectors. Keep a kill switch.

### Q102. Counterfactual evaluation for production decisions
Log propensities (probability of the chosen action) when serving stochastic policies; this enables unbiased OPE (IPS/DR) for new policies. Without logged propensities, offline evaluation is unreliable.

### Q103. Non-stationarity in real systems
User behaviour, markets and fleets drift. Use sliding-window/discounted learning, periodic retraining, drift detection, context features (time, season) and ensembles; evaluate on recent data.

### Q104. Meta-RL and fast adaptation
Learn to adapt quickly to new tasks: MAML-style gradient meta-learning, RL² (RNN-based), context-based adaptation (PEARL), in-context RL with Transformers. Useful for varied environments but data- and compute-hungry.

### Q105. Transfer and multi-task RL
Share representations, use pre-trained visual encoders (R3M, VC-1), policy distillation, successor features, and language-conditioned policies. Beware negative transfer and gradient conflicts.

### Q106. Exploration at scale
RND/curiosity, intrinsic motivation, population-based methods, count-based bonuses, and demonstration-seeded exploration. In real systems exploration is constrained by safety/business cost: use conservative exploration (bounded perturbations, Thompson sampling within safe sets).

### Q107. World models and planning
Learn latent dynamics (RSSM in Dreamer), plan with MPC/CEM/MCTS, train policies from imagined rollouts. Evaluate model accuracy over horizons and use uncertainty-aware planning; combine with real-data corrections.

### Q108. Evaluating RL beyond mean return
Report distributional metrics (IQM, optimality gap, performance profiles, as recommended by "Deep RL at the Edge of the Statistical Precipice"), number of seeds (≥5–10), sample complexity, wall-clock, robustness and safety violations.

### Q109. Hyper-parameter tuning workflow
Fix environment and evaluation protocol; start from library defaults; tune a few sensitive parameters (LR, batch/rollout size, entropy, γ/λ, network size) with multi-seed evaluation and early pruning (Optuna/ASHA); avoid overfitting to seeds; re-run final configs with fresh seeds.

### Q110. Debugging reward and environment first
Most RL failures are environment or reward bugs. Test with scripted policies, check reward scale and sign, observation ranges, termination logic, action mapping, determinism with seeds, and visualise episodes before blaming the algorithm.

### Q111. Engineering for training infrastructure
Actors/learner separation, vectorised envs, shared-memory buffers, checkpoint-resume, experiment tracking (W&B/MLflow), config management (Hydra), deterministic seeding, and cost controls (spot instances, early stopping).

### Q112. Interpreting and auditing policies
Analyse value/advantage maps, action distributions by state clusters, saliency for pixel policies, behavioural tests with scenario libraries, counterfactual simulations, and distillation into decision trees for inspection where possible.

### Q113. Combining RL with optimisation/OR
Use RL for sequential decisions with uncertainty and OR solvers (MIP, heuristics) for combinatorial structure: learn heuristics inside solvers, or use RL to generate actions that a solver repairs for feasibility.

### Q114. Reward modelling beyond preferences
Learned reward from demonstrations (IRL), ranked trajectories (T-REX), language-specified rewards (LLM-generated reward code such as Eureka), and multi-objective reward vectors with Pareto-front policies.

### Q115. Business case assessment for RL
Check: sequential decisions with delayed impact? Cheap/safe simulator or abundant logged data with propensities? Clear measurable reward? Baseline headroom? If not, prefer supervised learning, bandits, heuristics or OR.

```python
import numpy as np
n = 4                                    # 4x4 grid, goal at (3,3), step cost -1
gamma, V = 0.99, np.zeros((n, n))
moves = [(-1, 0), (1, 0), (0, -1), (0, 1)]
for _ in range(200):
    new = V.copy()
    for i in range(n):
        for j in range(n):
            if (i, j) == (n - 1, n - 1): continue
            vals = []
            for di, dj in moves:
                ni, nj = min(max(i + di, 0), n - 1), min(max(j + dj, 0), n - 1)
                vals.append(-1 + gamma * V[ni, nj])
            new[i, j] = max(vals)
    if np.abs(new - V).max() < 1e-6: break
    V = new
print(V.round(2))
```

### Task 5. DQN from scratch (core update)
```python
import torch, torch.nn as nn, random
from collections import deque

q = nn.Sequential(nn.Linear(4, 128), nn.ReLU(), nn.Linear(128, 128), nn.ReLU(), nn.Linear(128, 2))
q_t = nn.Sequential(*[nn.Linear(4, 128), nn.ReLU(), nn.Linear(128, 128), nn.ReLU(), nn.Linear(128, 2)])
q_t.load_state_dict(q.state_dict())
opt = torch.optim.Adam(q.parameters(), 1e-3); buf = deque(maxlen=100_000)

def update(batch=64, gamma=0.99):
    s, a, r, s2, d = map(torch.tensor, zip(*random.sample(buf, batch)))
    s, s2 = s.float(), s2.float(); a = a.long(); r = r.float(); d = d.float()
    with torch.no_grad():
        a2 = q(s2).argmax(1, keepdim=True)                       # Double DQN: select with online
        target = r + gamma * (1 - d) * q_t(s2).gather(1, a2).squeeze(1)   # evaluate with target
    loss = nn.functional.smooth_l1_loss(q(s).gather(1, a[:, None]).squeeze(1), target)
    opt.zero_grad(); loss.backward(); nn.utils.clip_grad_norm_(q.parameters(), 10); opt.step()
```
Sync `q_t` periodically (`q_t.load_state_dict(q.state_dict())`) or with Polyak averaging.

### Task 6. REINFORCE with a baseline (core)
```python
def reinforce_loss(logps, rewards, values, gamma=0.99):
    G, returns = 0, []
    for r in reversed(rewards): G = r + gamma * G; returns.insert(0, G)
    returns = torch.tensor(returns); returns = (returns - returns.mean()) / (returns.std() + 1e-8)
    adv = returns - values.detach()
    return -(torch.stack(logps) * adv).mean() + 0.5 * (returns - values).pow(2).mean()
```

### Task 7. PPO clipped loss (core)
```python
def ppo_loss(new_logp, old_logp, adv, clip=0.2):
    ratio = (new_logp - old_logp).exp()
    adv = (adv - adv.mean()) / (adv.std() + 1e-8)
    return -torch.min(ratio * adv, ratio.clamp(1 - clip, 1 + clip) * adv).mean()
```

# 🐞 Part 7: Debugging Scenarios

### D1. Reward never improves
Check the environment first: reward sign/scale, termination conditions, observation correctness, action mapping. Verify a scripted policy can earn reward. Then check LR, exploration, and whether rewards are too sparse.

### D2. Learning curve rises then collapses
Policy update too large (PPO clip/LR too high), entropy collapse, value-function instability, or catastrophic forgetting with replay. Lower LR, add entropy, normalise advantages, clip gradients, use checkpointing and early stopping.

### D3. Different seeds give wildly different results
High RL variance is normal but extreme spread signals sensitivity. Increase seeds, tune robustly, normalise observations/rewards, and report distributional statistics.

### D4. Q-values explode (DQN)
Overestimation, missing target network updates, unscaled rewards, or terminal-state handling bug. Use Double DQN, Huber loss, reward clipping/scaling, gradient clipping and correct `done` masking.

### D5. Agent exploits a loophole (reward hacking)
Inspect trajectories, log reward components, add constraints/penalties, fix simulator bugs, and use independent evaluation metrics not used for training.

### D6. Truncation vs termination bug
Treating time-limit truncation as terminal teaches the value to drop to zero at the cut-off. Bootstrap on truncation (use `terminated`, not `done`) and consider adding remaining-time as an observation.

### D7. Policy works in training, fails in evaluation
Observation normalisation stats not saved/applied, stochastic vs deterministic action difference, different env wrappers, or different seeds/initial states. Evaluate with identical wrappers and load normalisation.

### D8. Continuous-control agent jitters
Action noise too high, no action smoothing, high-frequency policy outputs. Add action-rate penalties, lower noise, use frame-skip, or low-pass filters; check control frequency vs simulator step.

### D9. Slow training throughput
Env step bottleneck, small rollout batches, Python overhead, GPU underused. Use vectorised/parallel envs, larger batches, JIT/GPU simulators, avoid CPU↔GPU transfers per step.

### D10. Entropy collapses to zero too early
Entropy coefficient too low, large LR, reward scale too large. Increase entropy bonus, anneal gradually, normalise rewards, and monitor KL/entropy.

### D11. Offline RL policy performs badly online
Extrapolation error and distribution shift. Use conservative methods (CQL/IQL/TD3+BC), constrain to dataset support, verify dataset coverage, and do small online evaluations before rollout.

### D12. Multi-agent training oscillates
Non-stationarity from simultaneous learning. Use CTDE (MAPPO/QMIX), parameter sharing, opponent pools, slower learning rates and population-based evaluation.

### D13. RLHF policy produces verbose, sycophantic answers
Reward-model bias (length/agreement) exploited. Increase KL penalty, add length normalisation or constraints, retrain reward models with counter-examples, and evaluate with held-out human preferences.

### D14. PPO KL divergence spikes
Too many epochs, too large LR, small batch. Reduce epochs/LR, use KL early stopping (target KL), increase batch size.

### D15. Policy fails after sim-to-real transfer
Dynamics mismatch, latency, sensor noise. Add domain randomisation, model delays/noise, system identification, and fine-tune with real data under safety constraints.

# 🧩 Part 8: Tricky Questions

### T1. Is Q-learning on-policy or off-policy?
Off-policy: the target uses `max_{a'} Q(s',a')`, independent of the action actually taken by the behaviour policy.

### T2. Why can SARSA be "safer" than Q-learning?
SARSA's target includes the exploratory action's risk, so near hazards it learns to keep a safe margin, whereas Q-learning learns the optimal greedy path that may be risky under ε-exploration.

### T3. Why does PPO use multiple epochs on the same data safely?
The clipped objective limits how far the new policy can move from the data-collecting policy, keeping importance ratios near 1.

### T4. Is a higher discount factor always better?
No. Higher γ increases variance and horizon length, slowing learning; the true objective may be short-horizon. Tune γ with the task's effective horizon.

### T5. Why can't DQN be used for continuous actions directly?
It requires `max_a Q(s,a)`, which is intractable over continuous spaces without discretisation or an actor network.

### T6. Do rewards need to be positive?
No. Sign matters for incentives (e.g., a negative per-step reward encourages fast termination, a positive one may encourage stalling). Design rewards with episode termination behaviour in mind.

### T7. Does RL always need a simulator?
No: offline RL, bandits and online learning from real interaction exist, but real-world exploration is costly and risky, so simulation or logged data is strongly preferred.

### T8. Is the policy gradient estimate biased when subtracting a baseline?
No, if the baseline doesn't depend on the action. It reduces variance without bias.

### T9. Why does experience replay not work for vanilla policy gradients?
Policy gradients are on-policy; old data come from a different policy and need importance-sampling corrections (as in off-policy actor-critic methods).

### T10. Is a high training reward proof of a good agent?
No. It may reflect reward hacking, overfitting to the training environment/seed, or exploitation of simulator bugs. Evaluate on held-out conditions and independent metrics.

### T11. Why is evaluation with a deterministic policy sometimes worse?
For stochastic-policy algorithms, the mean action may not equal the best action, especially in multimodal or partially observable settings. Compare both modes.

### T12. Why can adding more environments reduce sample efficiency?
Parallel envs improve wall-clock, not samples per update quality; large batches may need LR/rollout adjustments. Total environment steps to a given performance can increase.

### T13. Is RLHF the same as RL?
RLHF applies RL machinery (policy optimisation) with a learned reward from human preferences and a KL anchor; the "environment" is usually single-step prompt → response, closer to a contextual bandit than classic multi-step RL.

### T14. Does DPO need a reward model or RL loop?
No explicit ones; it derives an implicit reward from the policy/reference log-ratio and trains with a supervised-style loss on preference pairs.

### T15. Is multi-agent RL just single-agent RL with more agents?
No. Other agents make the environment non-stationary from each agent's view, adding equilibrium, coordination and credit-assignment challenges.

# 🔬 Part 12: Internals

### Why TD targets are biased but low variance
They use the current estimate `V(s')` in the target, so errors propagate (bias) but only one random transition is involved (low variance). Monte Carlo uses the full sampled return (unbiased, high variance). n-step and TD(λ) interpolate.

### Policy gradient derivation (sketch)
`J(θ)=E_τ[R(τ)]`; using the log-derivative trick `∇P = P ∇ log P`, `∇J = E[ R(τ) Σ_t ∇ log π_θ(a_t|s_t) ]` (the dynamics terms vanish). Reward-to-go and baselines further reduce variance.

### Why PPO's clip works
For positive advantage, the objective stops increasing once `r>1+ε`; for negative advantage, once `r<1−ε`. This removes the incentive for large policy shifts but is not a hard constraint (ratios can still exceed bounds via side effects), which is why KL monitoring and early stopping are used.

### Soft Actor-Critic objective
Policy maximises `E[Q(s,a) − α log π(a|s)]`; critics minimise soft Bellman error with target `r + γ(min Q' − α log π(a'|s'))`; α is tuned to reach a target entropy.

### DQN loss and gradients
Gradient flows only through `Q(s,a;θ)`, not the target (computed with `θ⁻` under `no_grad`). Huber loss and gradient clipping bound the effect of outlier TD errors.

### GAE as an exponentially weighted sum
`A_t = Σ_{l≥0}(γλ)^l δ_{t+l}` computed efficiently by a backward recursion `A_t = δ_t + γλ A_{t+1}`, with masks for episode ends.

### Importance ratio in PPO
`r_t = exp(logπ_new − logπ_old)`; always compute in log space for stability. Old log-probs are stored during rollout.

### RLHF objective
`max_θ E_{x,y~π_θ}[ r_φ(x,y) − β·KL(π_θ(·|x) ‖ π_ref(·|x)) ]`. The KL term can be applied per token as a reward penalty. The optimal policy under this objective has the form `π* ∝ π_ref · exp(r/β)`, which DPO exploits.

### Vectorised env auto-reset
When an env in a vector finishes, it resets immediately and returns the new first observation, so the real final observation is in `info`. Using it incorrectly corrupts bootstrap targets.

### Replay buffer sampling
Uniform sampling is O(1); prioritized replay uses a sum-tree (O(log N)) with importance-sampling weights to correct bias introduced by non-uniform sampling.

# ⚠️ Part 16: Common Mistakes

- Debugging the algorithm before validating the environment, reward and termination logic.
- Treating time-limit truncation as true termination (or the reverse).
- Judging by a single seed or a single training curve.
- Not normalising observations/rewards and forgetting to save the normaliser.
- Evaluating with different wrappers/seeds than training.
- Reward functions with unintended shortcuts; no inspection of agent behaviour.
- Using off-policy replay with on-policy algorithms.
- Setting γ, learning rate or batch size without regard to horizon and noise.
- Ignoring exploration (ε decay too fast, entropy collapse).
- Skipping simple baselines (heuristics, bandits, behaviour cloning).
- Training and tuning on the same seeds reported as final results.
- Deploying offline-RL policies without conservative methods or OPE.
- Logging deterministic decisions without propensities, which blocks counterfactual evaluation.
- Underestimating sim-to-real gap and safety requirements.
- In RLHF: weak KL control and trusting reward-model scores as truth.

# 🧾 Part 18: Cheat Sheet & Last-Minute Revision

### Core equations
```
G_t = r_{t+1} + γ r_{t+2} + ...
V(s) = E[r + γ V(s')]               Q*(s,a) = E[r + γ max_a' Q*(s',a')]
Q-learning: Q += α (r + γ max Q' − Q)    SARSA: Q += α (r + γ Q(s',a') − Q)
policy gradient: ∇J = E[∇ log π(a|s) · A(s,a)]
GAE: A_t = Σ (γλ)^l δ_{t+l},  δ_t = r_t + γV(s_{t+1}) − V(s_t)
PPO: L = E[min(r A, clip(r,1−ε,1+ε) A)]
SAC: maximise E[r + α H(π)]         DPO: −log σ(β[Δπ_w − Δπ_l])
```

### Algorithm picker
Discrete & simple → DQN/PPO • Continuous → SAC/TD3/PPO • Sparse goals → HER • Fixed logs → CQL/IQL • Independent decisions → bandits • Multi-agent → MAPPO/QMIX • LLM alignment → DPO/PPO/GRPO.

### Debug checklist
Env sanity (scripted policy, ranges, determinism) → reward scale/sign/components → termination vs truncation → normalisation → hyper-parameter defaults → diagnostics (entropy, KL, value loss, explained variance) → multi-seed runs → compare with baselines.

### Deployment checklist
Held-out scenario tests • constraints and action limits • shadow mode • propensity logging • monitoring of reward/constraint violations • fallback policy and kill switch • retraining and drift plan.
