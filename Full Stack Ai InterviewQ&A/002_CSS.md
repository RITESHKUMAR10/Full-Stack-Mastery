# 🟢 Part 1: Fresher (0–1 year)

### Q1. What is CSS? Why do we use it? *(Conceptual)*
**Answer:** CSS (Cascading Style Sheets) controls the **presentation** of HTML: color, layout, fonts, spacing and animation. HTML = structure, CSS = style, JS = behavior. Benefits: **separation of concerns**, one stylesheet for the whole site (maintainability), caching (external file), and responsive design.

```css
h1 {
  color: #4f46e5;
  font-size: 2rem;
}
```
Syntax: `selector { property: value; }` (one rule = a selector + a declaration block).

### Q2. In how many ways can you add CSS to HTML? *(Comparison)*
| Method | How | When |
|---|---|---|
| Inline | `<p style="color:red">` | Dynamic JS values, HTML emails; otherwise avoid |
| Internal | `<style>` in the head | Single page, critical CSS |
| External | `<link rel="stylesheet" href="a.css">` | **Best**: cacheable and reusable |
| `@import` | `@import url(a.css)` | Avoid (waterfall, slow) |

**Follow-up:** `<link>` vs `@import`? `<link>` downloads in parallel. `@import` starts only after the first CSS file is parsed (a chain).

### Q3. What are the types of CSS selectors? *(Conceptual)*
```css
* { }                      /* universal */
p { }                      /* element/type */
.card { }                  /* class */
#hero { }                  /* id */
a[target="_blank"] { }     /* attribute */
a[href^="https"] { }       /* starts with; $= ends with, *= contains */
ul li { }                  /* descendant */
ul > li { }                /* direct child */
h1 + p { }                 /* adjacent sibling */
h1 ~ p { }                 /* general sibling */
a:hover { }                /* pseudo-class */
p::first-line { }          /* pseudo-element */
h1, h2, h3 { }             /* group */
```

### Q4. What is the box model? Why use `box-sizing: border-box`? *(Must-know)*
**Answer:** Every element is a box: **content → padding → border → margin** (from inside to outside).
- `content-box` (default): `width` is only the content. Total = width + padding + border.
- `border-box`: `width` includes padding and border. Layout is predictable.

```css
*, *::before, *::after { box-sizing: border-box; }

.box { width: 200px; padding: 20px; border: 5px solid; }
/* content-box -> total 250px | border-box -> total 200px */
```
Margin is **outside** the box, is not counted in width, and has no background.

### Q5. How is CSS specificity calculated? *(Must-know)*
**Answer:** Think of specificity as `(a, b, c)`:
- **a** = id selectors
- **b** = classes, attributes, pseudo-classes
- **c** = elements, pseudo-elements

Inline style is higher; `!important` is higher still. With equal specificity, the rule **written later** wins.
```css
p            { color: black; }   /* (0,0,1) */
.card p      { color: blue; }    /* (0,1,1) */
#hero .card p{ color: red; }     /* (1,1,1) */
```
`:where()` = 0. `:is()`, `:not()`, `:has()` take the highest specificity among their arguments. `*` = 0.

### Q6. `display: none` vs `visibility: hidden` vs `opacity: 0`? *(Comparison)*
| | Takes space | Click/events | Screen reader | Can transition |
|---|---|---|---|---|
| `display:none` | ❌ | ❌ | ❌ | ❌ (directly) |
| `visibility:hidden` | ✅ | ❌ | ❌ | ✅ |
| `opacity:0` | ✅ | ✅ | ✅ | ✅ |

### Q7. What are the `position` types? *(Conceptual)*
- `static` (default): normal flow; `top/left/z-index` do nothing
- `relative`: offset from its original place; its space is kept; the reference for absolute children
- `absolute`: removed from flow; placed relative to the **nearest positioned ancestor**
- `fixed`: relative to the viewport (does not move on scroll)
- `sticky`: relative until a scroll threshold, then fixed (inside its scroll container)

```css
.parent { position: relative; }
.badge  { position: absolute; top: -8px; right: -8px; }
```

### Q8. What is the difference between `em`, `rem`, `%`, `vw/vh` and `px`?
- `px`: fixed
- `em`: relative to **the element's own font-size** (also in padding/margin); compounds when nested
- `rem`: relative to the **root (html) font-size**: scalable and predictable ✅
- `%`: relative to the parent (which parent property depends on the property)
- `vw/vh`: 1% of the viewport; on mobile use `dvh/svh` (address-bar issue)

### Q9. Pseudo-class vs pseudo-element? *(Comparison)*
- **Pseudo-class** (`:`) = a **state** of the element (`:hover, :focus, :first-child, :checked, :disabled`)
- **Pseudo-element** (`::`) = a **virtual part** of the element (`::before, ::after, ::first-letter, ::selection, ::placeholder`)

`::before/::after` need the `content` property (an empty string is fine).
```css
.btn::after { content: " →"; }
```

### Q10. What is inheritance? Which properties are inherited?
**Inherited:** `color, font-family, font-size, font-weight, line-height, text-align, letter-spacing, visibility, cursor, list-style, white-space, direction`.
**Not inherited:** `margin, padding, border, background, width, height, display, position, overflow, z-index, opacity, transform`.
To force a value: `inherit`, `initial`, `unset`, `revert`.

### Q11. What are `float` and `clear`? When do you use them?
`float` pushes an element left or right, and text wraps around it (originally for image-text wrapping). For layout, use Flex/Grid today. A floated child makes the parent's height collapse, so we use a **clearfix**:
```css
.clearfix::after { content: ""; display: table; clear: both; }
/* or modern: parent { display: flow-root; } */
```

### Q12. `margin` vs `padding`?
Padding = space **inside** the border (the background shows there). Margin = space **outside** the border (transparent, can collapse, can be negative). Padding increases the clickable area; margin does not.

### Q13. What is `!important`? When should you use it?
It overrides specificity. Avoid it. Use it only for utility classes (`.hidden { display:none !important }`), third-party overrides, or accessibility overrides (reduced motion). Overuse leads to specificity wars.

### Q14. Block vs inline vs inline-block?
Block: new line, full width, width/height/margin all work. Inline: stays in the flow, width/height are **ignored**, vertical margins are ignored. Inline-block: flows like inline, but width/height apply. (Gotcha: HTML whitespace creates a ~4px gap between inline-blocks.)

### Q15. What are the color formats?
Named (`tomato`), hex (`#ff6347`, `#f634`), `rgb()/rgba()`, `hsl()/hsla()`, modern `hwb()`, `lab()/lch()`, **`oklch()`** (perceptually uniform), `color-mix()`, `currentColor`, `transparent`.
```css
color: rgb(79 70 229 / 0.5);
color: oklch(60% 0.2 280);
background: color-mix(in srgb, #4f46e5 70%, white);
```

### Q16. What are the basic text and font properties?
`font-family` (with a fallback stack), `font-size`, `font-weight`, `font-style`, `line-height` (unitless is best), `text-align`, `text-decoration`, `text-transform`, `letter-spacing`, `word-spacing`, `text-overflow`, `white-space`.
```css
body { font-family: Inter, system-ui, -apple-system, "Segoe UI", sans-serif; line-height: 1.6; }
```

### Q17. What are the background properties?
`background-color, -image, -repeat, -position, -size (cover/contain), -attachment, -clip, -origin`; shorthand `background`. Multiple backgrounds are separated by commas.
```css
.hero { background: linear-gradient(#0008,#0008), url(hero.jpg) center/cover no-repeat; }
```
`cover` fills the whole area (may crop). `contain` shows the whole image (may leave gaps).

### Q18. CSS reset vs normalize?
A **reset** removes all default styles (margin 0, etc.). **Normalize.css** makes browser defaults consistent but keeps useful defaults. The modern approach is a small "modern reset" (`box-sizing`, `margin:0`, `img{max-width:100%}`).

### Q19. What does `overflow` do?
`visible` (default), `hidden` (clip), `scroll`, `auto` (scrollbar only when needed), `clip`. `overflow-x/y` are separate. `overflow: hidden` also creates a BFC and can break `position: sticky`.

### Q20. What is `z-index`?
It controls the stack order of overlapping elements. It works only on **positioned** elements (and flex/grid items). Higher = on top. It is compared only **inside the same stacking context** (see Part 3).

# 🔵 Part 2: Junior (1–3 years)

### Q21. What is Flexbox? What are its main properties? *(Must-know)*
A 1-D layout (a row **or** a column). **Container:** `display:flex; flex-direction; flex-wrap; justify-content (main axis); align-items (cross axis); align-content (multi-line); gap`. **Item:** `flex-grow, flex-shrink, flex-basis, flex (shorthand), align-self, order`.
```css
.nav { display: flex; justify-content: space-between; align-items: center; gap: 1rem; }
.item { flex: 1 1 0; }   /* grow, shrink, basis */
```
Shorthand: `flex: 1` = `1 1 0%`, `flex: auto` = `1 1 auto`, `flex: none` = `0 0 auto`, default = `0 1 auto`.
Axis note: with `flex-direction: column`, the main axis is vertical (so `justify-content` works vertically!).

### Q22. What is CSS Grid? Basic usage?
A 2-D layout (rows + columns).
```css
.layout {
  display: grid;
  grid-template-columns: 240px 1fr;
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
  gap: 1rem;
}
header { grid-area: header; }
```
`fr` = a fraction of free space. Also: `repeat()`, `minmax()`, `auto-fit/auto-fill`, `span`, `grid-auto-flow`.

### Q23. Flexbox vs Grid: when to use which? *(Comparison)*
Flex = 1-D, **content-driven** (item sizes shape the layout), good inside components (navbar, button row). Grid = 2-D, **layout-driven** (the container defines the structure), good for page layout. Use them together.

### Q24. How do you center a div? (all ways)
```css
/* 1. Grid (shortest) */
.parent { display: grid; place-items: center; min-height: 100vh; }
/* 2. Flex */
.parent { display: flex; justify-content: center; align-items: center; }
/* 3. Absolute + transform */
.child { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }
/* 4. Absolute + inset + margin auto (fixed size) */
.child { position: absolute; inset: 0; margin: auto; width: 200px; height: 100px; }
/* 5. Horizontal only */
.child { width: 300px; margin-inline: auto; }
/* 6. Text */
.parent { text-align: center; line-height: 100px; }
```

### Q25. What is margin collapse?
Vertical margins (sibling-sibling, parent-first/last child, empty block) overlap and become **equal to the larger one** (they do not add up). It does not happen for flex/grid items, floats, absolute elements, inline-block, or inside a BFC. Fix: padding/border, `display: flow-root`, or `gap`.
```css
.a { margin-bottom: 30px; } .b { margin-top: 20px; }  /* gap = 30px, not 50 */
```

### Q26. What are media queries and the mobile-first approach?
```css
.card { padding: 1rem; }                              /* mobile default */
@media (min-width: 768px)  { .card { padding: 2rem; } }
@media (min-width: 1024px) { .card { display: flex; } }
@media (prefers-color-scheme: dark) { :root { --bg: #111; } }
@media (prefers-reduced-motion: reduce) { * { animation: none !important; } }
@media (hover: hover) and (pointer: fine) { .btn:hover { ... } }
@media print { nav { display: none; } }
```
Mobile-first = base styles for small screens, then enhance with `min-width` (less overriding, better performance). Choose breakpoints from the **content**, not from devices.

### Q27. CSS Variables (Custom Properties)
```css
:root { --primary: #4f46e5; --radius: 8px; }
.btn { background: var(--primary); border-radius: var(--radius, 4px); }  /* fallback */
[data-theme="dark"] { --primary: #818cf8; }
```
Sass variables are **compile-time**. CSS variables are **runtime** (they cascade and inherit, JS can set them with `el.style.setProperty('--x', ...)`, and media queries can change them).

### Q28. Transitions and animations?
```css
.btn { transition: transform .2s ease, background-color .2s; }
.btn:hover { transform: translateY(-2px); }

@keyframes pulse { 0%,100% { transform: scale(1); } 50% { transform: scale(1.1); } }
.dot { animation: pulse 1.5s ease-in-out infinite; }
```
Transition = state A → B (needs a trigger). Animation = multi-step with keyframes, runs automatically. Properties: duration, timing-function, delay, iteration-count, direction, fill-mode, play-state.

### Q29. What is `transform`?
`translate, rotate, scale, skew, matrix`, and 3D (`perspective, rotateX/Y`). It does not affect layout (the original space stays) and it is GPU-friendly. `transform-origin` sets the pivot. Modern individual properties: `translate: 10px; rotate: 45deg; scale: 1.2`.

### Q30. `object-fit` and `aspect-ratio`
```css
img { width: 100%; height: 240px; object-fit: cover; object-position: center; }
.thumb { aspect-ratio: 16 / 9; }
```
`object-fit`: `cover` (crop), `contain` (fit), `fill` (stretch), `none`, `scale-down`.

### Q31. How do you truncate text with an ellipsis (...)?
```css
.one-line { white-space: nowrap; overflow: hidden; text-overflow: ellipsis; }

.three-lines {
  display: -webkit-box; -webkit-line-clamp: 3; -webkit-box-orient: vertical;
  overflow: hidden;
  line-clamp: 3;  /* standard (support is growing) */
}
```

### Q32. `calc()`, `min()`, `max()`, `clamp()`
```css
width: calc(100% - 2rem);          /* spaces around + and - are required */
width: min(90%, 1200px);
padding: max(1rem, 3vw);
font-size: clamp(1rem, 2.5vw + .5rem, 2rem);   /* min, preferred, max */
```

### Q33. Structural pseudo-classes: `nth-child` vs `nth-of-type`
`:nth-child(n)` = position among **all children** of the parent (any tag). `:nth-of-type(n)` = position among elements of the **same tag**. Formulas: `2n+1` (odd), `2n` (even), `-n+3` (first 3), `n+4` (4th onward).
```css
li:nth-child(odd) { background: #f6f6f6; }
```

### Q34. Attribute selectors?
`[disabled]`, `[type="text"]`, `[href^="https"]`, `[href$=".pdf"]`, `[class*="btn"]`, `[lang|="en"]`, case-insensitive `[type="TEXT" i]`.

### Q35. `inherit`, `initial`, `unset`, `revert`, `all`
`inherit` takes the parent's value, `initial` is the spec default, `unset` (acts as inherit for inherited properties, otherwise initial), `revert` goes back to the browser/user stylesheet. `all: unset` resets everything (component isolation).

### Q36. Gradients, shadows, filters
```css
background: linear-gradient(135deg, #4f46e5, #ec4899);
background: radial-gradient(circle at top, #fff, #000);
background: conic-gradient(red, yellow, green);
box-shadow: 0 4px 12px rgb(0 0 0 / .15), inset 0 1px 0 #fff;
text-shadow: 0 1px 2px #0006;
filter: blur(4px) brightness(1.1) drop-shadow(0 2px 4px #0004);
backdrop-filter: blur(10px);       /* glassmorphism */
```
`box-shadow` follows the box. `filter: drop-shadow` follows the actual shape (transparent PNG/SVG).

### Q37. `pointer-events`, `cursor`, `user-select`, `resize`
`pointer-events: none` lets the click pass through to what is below. `user-select: none` stops text selection. `cursor: pointer/not-allowed/grab`. `resize: both|vertical` (textarea).

### Q38. How do you make a sticky header?
```css
header { position: sticky; top: 0; z-index: 100; background: #fff; }
```
If it does not work: an ancestor has `overflow: hidden/auto/scroll`, `top` is missing, or the parent is only as tall as the sticky element.

### Q39. What is BEM naming?
Block__Element--Modifier: `.card`, `.card__title`, `.card--featured`. Predictable, flat specificity, no tooling needed.

### Q40. Vendor prefixes and Autoprefixer
`-webkit- -moz- -ms- -o-` were used for experimental features. Do not write them by hand today: **Autoprefixer** (PostCSS) adds them based on your browserslist.

### Q41. `@font-face` and web fonts
```css
@font-face {
  font-family: "Inter";
  src: url("/fonts/inter.woff2") format("woff2");
  font-weight: 100 900;          /* variable font */
  font-display: swap;
  unicode-range: U+0000-00FF;
}
```
`font-display`: `swap` (show fallback first, then swap: FOUT), `block` (invisible text first: FOIT), `optional` (on a slow network, keep the fallback), `fallback`.

### Q42. Lists and counters
```css
ol { counter-reset: step; list-style: none; }
ol li::before { counter-increment: step; content: "Step " counter(step) ": "; }
li::marker { color: tomato; }
```

# 🟡 Part 3: Mid (3–5 years)

### Q43. What is a stacking context? Why does `z-index` not work? *(Must-know)*
`z-index` works only on positioned (or flex/grid) items, and it is compared **only inside its own stacking context**. A new stacking context is created by: the root `html`, `position` + a `z-index` (not auto), `opacity < 1`, `transform`, `filter`, `perspective`, `will-change`, `isolation: isolate`, `mix-blend-mode`, a flex/grid child with z-index, and `contain: paint`.
If the parent's context is low, a child with `z-index: 9999` still cannot go above elements outside that parent.
```css
.modal-root { isolation: isolate; }   /* a clean way to stop z-index wars */
```
Order inside one context: background → negative z → block → float → inline → z-index auto/0 → positive z.

### Q44. What is a BFC (Block Formatting Context)?
A region where block layout is isolated (floats and margins inside do not leak out). Triggers: `overflow` other than visible, `display: flow-root`, `float`, `position: absolute/fixed`, `inline-block`, `table-cell`, flex/grid containers. Uses: clear floats, stop margin collapse, stop text wrapping around a float.

### Q45. Reflow, repaint and composite: which properties should you animate?
- **Layout (reflow):** `width, height, margin, padding, top/left, font-size, display` → expensive
- **Paint (repaint):** `color, background, box-shadow, border-radius, visibility`
- **Composite only:** `transform`, `opacity` (and sometimes `filter`) → GPU, 60fps

```css
.card { transition: transform .3s, opacity .3s; will-change: transform; }
.card:hover { transform: translateY(-4px) scale(1.02); }
```
Use `will-change` only when needed and remove it after the animation (it uses memory, creates a new layer and a stacking context).

### Q46. CSS architecture: BEM vs CSS Modules vs utility-first vs CSS-in-JS
| Approach | Pros | Cons |
|---|---|---|
| BEM + Sass | Predictable, no runtime | Needs discipline, global scope |
| CSS Modules | Scoped by default, zero runtime | Limited dynamic theming |
| Tailwind (utility) | Fast, small CSS, consistent | Noisy HTML, learning curve |
| Runtime CSS-in-JS (styled-components, emotion) | Dynamic props, colocated | Runtime cost, RSC/SSR issues |
| Zero-runtime (vanilla-extract, Panda, Linaria) | Type-safe, no runtime | Build setup |

### Q47. What are Container Queries? How are they different from media queries?
A media query checks the **viewport**. A container query checks the **size of the parent container**. Best for reusable components.
```css
.card-wrap { container-type: inline-size; container-name: card; }
@container card (min-width: 400px) {
  .card { display: grid; grid-template-columns: 1fr 2fr; }
}
/* units: cqw, cqh, cqi, cqb */
```

### Q48. `:is()`, `:where()`, `:has()`, `:not()`
```css
:is(h1,h2,h3):hover { color: teal; }          /* specificity = highest argument */
:where(.a, .b) p { margin: 0; }               /* specificity 0 (good for resets) */
.card:has(img) { padding: 0; }                /* parent selector */
form:has(:invalid) button { opacity: .5; }
label:has(+ input:required)::after { content: " *"; }
li:not(:last-child) { border-bottom: 1px solid #eee; }
```
Watch performance: a broad `:has()` (like `body:has(...)`) can be expensive.

### Q49. Fluid typography and spacing
```css
:root {
  --step-0: clamp(1rem, 0.9rem + 0.5vw, 1.25rem);
  --space: clamp(1rem, 2vw, 2rem);
}
h1 { font-size: clamp(1.75rem, 1rem + 3vw, 3rem); }
```
Accessibility: font-size in `vw` only breaks zoom, so always mix it with `rem`.

### Q50. Logical properties (RTL/i18n)
`margin-inline-start`, `padding-block`, `inset-inline-end`, `border-start-start-radius`, `inline-size`, `block-size`. They pick the correct side automatically for LTR, RTL and vertical writing modes.
```css
.card { padding-inline: 1rem; margin-block: 2rem; text-align: start; }
```

### Q51. What is Subgrid?
A child grid inherits the parent's tracks, so parts of nested cards (title/price/button) stay aligned across different cards.
```css
.cards { display: grid; grid-template-columns: repeat(3, 1fr); }
.card  { display: grid; grid-row: span 3; grid-template-rows: subgrid; }
```

### Q52. `auto-fit` vs `auto-fill`
Both are used in `repeat()`. `auto-fill` creates as many tracks as fit (empty tracks stay). `auto-fit` collapses empty tracks, so items stretch.
```css
grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
```

### Q53. Common flexbox bug: an item overflows (`min-width: 0`)
A flex item has `min-width: auto` by default (the content's minimum size), so long text or an image goes outside the container.
```css
.item { min-width: 0; }              /* needed for truncation in flex/grid children */
.text { overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }
```

### Q54. Cascade Layers (`@layer`)
In the cascade, **layer order is checked before specificity**. Unlayered styles beat layered styles (for normal rules). For `!important`, the order is reversed.
```css
@layer reset, base, components, utilities;
@layer components { .btn { padding: .5rem 1rem; } }
@layer utilities  { .p-0 { padding: 0; } }
/* import third-party CSS into a low layer: */
@import url(lib.css) layer(vendor);
```

### Q55. Native CSS Nesting
```css
.card {
  padding: 1rem;
  & .title { font-weight: 700; }
  &:hover { box-shadow: 0 4px 12px #0002; }
  @media (min-width: 768px) { padding: 2rem; }
}
```
You need Sass nesting less now, but Sass mixins, functions and loops are still useful.

### Q56. `@supports` (feature queries)
```css
.grid { display: flex; flex-wrap: wrap; }
@supports (display: grid) { .grid { display: grid; } }
@supports not (aspect-ratio: 1) { .thumb { padding-top: 56.25%; } }
@supports selector(:has(a)) { ... }
```
The main tool for progressive enhancement.

### Q57. How do you implement dark mode?
```css
:root { color-scheme: light dark; --bg: #fff; --fg: #111; }
@media (prefers-color-scheme: dark) { :root { --bg: #0b0b0f; --fg: #eee; } }
[data-theme="light"] { --bg: #fff; --fg: #111; }   /* manual override */
[data-theme="dark"]  { --bg: #0b0b0f; --fg: #eee; }
body { background: var(--bg); color: var(--fg); }
```
`color-scheme` also darkens form controls and scrollbars. To avoid a flash, put a small inline theme script in `<head>`. Save the preference in localStorage.
```css
background: light-dark(#fff, #111);   /* modern */
```

### Q58. `prefers-reduced-motion` and accessibility
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: .01ms !important; animation-iteration-count: 1 !important; transition-duration: .01ms !important; scroll-behavior: auto !important; }
}
```
Needed for users with vestibular disorders.

### Q59. How do you animate custom properties? (`@property`)
A normal custom property is just a string, so it cannot animate. Use `@property` to give it a type:
```css
@property --angle { syntax: "<angle>"; inherits: false; initial-value: 0deg; }
.ring { background: conic-gradient(from var(--angle), red, blue); animation: spin 3s linear infinite; }
@keyframes spin { to { --angle: 360deg; } }
```

### Q60. CSS Containment and `content-visibility`
```css
.card { contain: layout paint style; }                 /* isolate the subtree */
.section { content-visibility: auto; contain-intrinsic-size: auto 600px; }
```
Offscreen sections skip rendering, so the first render is faster. Without `contain-intrinsic-size`, the scrollbar jumps.

### Q61. Scroll snap
```css
.carousel { display: flex; overflow-x: auto; scroll-snap-type: x mandatory; scroll-behavior: smooth; }
.slide { flex: 0 0 100%; scroll-snap-align: start; }
```

### Q62. Sass/SCSS vs PostCSS vs native CSS
Sass: variables, nesting, mixins, functions, loops (build-time). PostCSS: a plugin pipeline (autoprefixer, cssnano, nesting). Native CSS now has variables, nesting, `color-mix`, `@layer` and `calc`, so Sass is optional.
```scss
@mixin respond($bp) { @media (min-width: $bp) { @content; } }
.card { @include respond(768px) { display: flex; } }
```

### Q63. How do CSS Modules work?
At build time, class names are hashed (`.title` → `.title_x7d2a`), so the scope is local. Use `:global()` for global styles and `composes` for reuse.
```jsx
import s from './Card.module.css';
<h2 className={s.title}>Ritesh Kumar</h2>
```

### Q64. Responsive images with CSS
`max-width: 100%; height: auto`, `object-fit`, `image-set()` for backgrounds, and HTML `<picture>`/`srcset` for content images (better).

### Q65. Why does `100vh` break on mobile?
The mobile browser's address bar is dynamic, and `100vh` is the largest viewport. Use `100dvh` (dynamic), `100svh` (small), `100lvh` (large) with a fallback.
```css
.hero { min-height: 100vh; min-height: 100dvh; }
```

# 🟠 Part 4: Senior (5–7 years)

### Q66. Design tokens and a scalable theming system *(Architecture)*
Three layers: **primitive** (`--blue-500`) → **semantic** (`--color-primary`, `--color-surface`) → **component** (`--btn-bg`). Components use only semantic/component tokens, so dark mode or a brand theme needs a change only in the semantic layer. Style Dictionary / Tokens Studio keep Figma and code in sync.
```css
:root { --blue-500: #3b82f6; --color-primary: var(--blue-500); }
[data-theme="brand-b"] { --color-primary: var(--green-600); }
.btn { --btn-bg: var(--color-primary); background: var(--btn-bg); }
```

### Q67. CSS performance: what is actually slow?
- **Render-blocking:** no paint until CSS is downloaded and parsed → inline critical CSS, load the rest async, keep files small
- **Selector matching:** the browser matches right to left; deep selectors, `*`, and broad `:has()` can cost, but modern engines usually handle them well; **layout and paint cost matter more**
- **Expensive paint:** large `box-shadow`, `filter: blur`, `backdrop-filter` on big areas
- **Layout thrashing:** interleaving reads and writes in JS
- **Large DOM + complex CSS:** slow style recalculation

Tools: DevTools Performance panel (Recalculate Style, Layout, Paint), Coverage tab (unused CSS), Lighthouse.

### Q68. Critical CSS and CSS delivery
```html
<style>/* above-the-fold critical CSS inline */</style>
<link rel="preload" href="/app.css" as="style" onload="this.rel='stylesheet'" />
<noscript><link rel="stylesheet" href="/app.css" /></noscript>
```
Tools: critical, Penthouse, automatic extraction in Next.js/Astro. Also: route-based CSS splitting, the `media="print"` trick, remove unused CSS (Tailwind JIT/PurgeCSS), Brotli, HTTP/2, long-term cache with hashed names.

### Q69. How do you prevent layout shift (CLS) with CSS?
Use `aspect-ratio` or width/height on media, reserve space for ads/embeds (`min-height`), `font-display: swap` with `size-adjust` / `ascent-override` on fallback fonts, skeletons with a fixed height, animate with `transform` (not top/left), and do not inject banners above existing content late.
```css
.thumb { aspect-ratio: 16/9; width: 100%; object-fit: cover; background: #eee; }
@font-face { font-family: "Inter Fallback"; src: local("Arial"); size-adjust: 107%; ascent-override: 90%; }
```

### Q70. Accessible focus, contrast and states
```css
:focus-visible { outline: 3px solid Highlight; outline-offset: 2px; }
button:focus:not(:focus-visible) { outline: none; }
```
Never use `outline: none` without a replacement. Contrast must be ≥ 4.5:1 (normal text) and 3:1 (large text/UI). Test `forced-colors: active` (Windows High Contrast): `@media (forced-colors: active) { .btn { border: 1px solid ButtonText; } }`. The visually-hidden pattern:
```css
.sr-only { position: absolute; width: 1px; height: 1px; margin: -1px; padding: 0; overflow: hidden; clip: rect(0 0 0 0); white-space: nowrap; border: 0; }
```

### Q71. High-performance animation: the FLIP technique
**F**irst (initial rect), **L**ast (final rect), **I**nvert (use transform to go back to the old position), **P**lay (animate the transform away). Instead of animating layout, you animate only `transform`.
```js
const first = el.getBoundingClientRect();
el.classList.toggle('expanded');                  // final layout
const last = el.getBoundingClientRect();
el.style.transform = `translate(${first.x - last.x}px, ${first.y - last.y}px)`;
requestAnimationFrame(() => { el.style.transition = 'transform .3s'; el.style.transform = ''; });
```
A modern alternative is the **View Transitions API**.

### Q72. How do you animate `height: auto`?
Not directly. Options: the `grid-template-rows: 0fr → 1fr` trick (best), the `max-height` hack (janky), measure with JS, or `interpolate-size: allow-keywords` (Chromium).
```css
.panel { display: grid; grid-template-rows: 0fr; transition: grid-template-rows .3s; }
.panel.open { grid-template-rows: 1fr; }
.panel > div { overflow: hidden; }
```

### Q73. How do you animate from `display: none` to visible?
Modern way: `@starting-style` + `transition-behavior: allow-discrete`.
```css
.modal { opacity: 1; transition: opacity .2s, display .2s allow-discrete; }
.modal.hidden { opacity: 0; display: none; }
@starting-style { .modal { opacity: 0; } }
```
Fallback: `visibility + opacity + pointer-events: none`.

### Q74. Modern color: `oklch`, `color-mix`, relative colors
```css
--brand: oklch(62% 0.19 275);
--brand-hover: oklch(from var(--brand) calc(l - 0.08) c h);
--tint: color-mix(in oklch, var(--brand) 20%, white);
```
OKLCH is perceptually uniform: changing lightness does not shift the hue, so building accessible palettes is easy.

### Q75. Scroll-driven animations and modern APIs
```css
.progress { animation: grow linear; animation-timeline: scroll(); transform-origin: 0 50%; }
@keyframes grow { from { transform: scaleX(0); } to { transform: scaleX(1); } }
```
`animation-timeline: view()` runs when the element enters the viewport. View Transitions: `document.startViewTransition()`. Check browser support and add an `@supports` fallback.

### Q76. Print stylesheet
```css
@media print {
  nav, .ads, button { display: none !important; }
  a[href^="http"]::after { content: " (" attr(href) ")"; }
  body { font: 12pt/1.4 serif; color: #000; background: #fff; }
  h2, img { break-inside: avoid; }
  @page { margin: 2cm; }
}
```

### Q77. RTL/i18n layout
`dir="rtl"` + logical properties, `:dir(rtl)`, mirror icons (`transform: scaleX(-1)`), `text-align: start`. Flex `row` reverses automatically in RTL. Use proper fonts per script and a taller `line-height` for Devanagari/Arabic.

### Q78. CSS testing and quality
- **Visual regression:** Playwright screenshots, Chromatic/Percy
- **Lint:** stylelint (property order, no-descending-specificity, no `!important`)
- **Cross-browser:** BrowserStack/Playwright matrix, `browserslist`, `@supports`
- **Perf/a11y:** Lighthouse CI, axe
- **Dead CSS:** Coverage tab, PurgeCSS

### Q79. Browser compatibility strategy
`browserslist` + Autoprefixer, `@supports` progressive enhancement, caniuse / MDN browser-compat data, fallback first (a basic flex layout, then enhance with grid/subgrid). Polyfills are a JS-side tool; for CSS, degrade gracefully. Rule: **the core experience works everywhere; enhancements work where supported.**

### Q80. Runtime CSS-in-JS cost and the RSC problem
Runtime libraries serialize and inject styles during render (CPU + bundle size). React Server Components and streaming have no context/hooks on the server, so these libraries do not fit. That is why the trend is zero-runtime (CSS Modules, Tailwind, vanilla-extract, Panda, StyleX).

### Q81. Managing specificity in a large codebase
Flat selectors (single class), `@layer` order, `:where()` for base styles, BEM/Modules, ban `#id` and `!important` with stylelint, no deep nesting (max 2–3 levels), design tokens, and the utility layer last.

### Q82. What is CSS Houdini?
A set of APIs to extend the browser's CSS engine: Properties & Values API (`@property`), Paint API (custom `paint()`), Layout API, Animation Worklet. Adoption is limited; `@property` is the most practical.

# 🐞 Part 7: Debugging Scenarios

### D1. I set `z-index: 9999` but the element is not on top.
Cause: `position: static` (z-index does nothing), or a different **stacking context** (a parent has `transform/opacity/filter`). Fix: use `position: relative`, find the parent's context (DevTools 3D view / Layers), or portal the modal to the end of `body`.

### D2. Text in a flex item overflows the container.
A flex item has `min-width: auto`. Fix: `min-width: 0` plus `overflow: hidden` / `overflow-wrap: anywhere`.

### D3. `height: 100%` does not work.
The parent has no explicit height. A percentage height needs a defined parent height (the whole chain `html, body { height: 100% }`). Or use `min-height: 100dvh`, or flex/grid.

### D4. `position: sticky` does not work.
An ancestor has `overflow: hidden/auto/scroll`; `top/bottom` is not set; the parent is only as tall as the sticky element; inside a flex container it needs `align-self: start`.
```css
.sidebar { position: sticky; top: 1rem; align-self: start; }
```

### D5. A transition does not animate (height: auto, display: none).
`auto` and `display` cannot be interpolated. Fix: use the techniques in Q72/Q73, fixed values, or `visibility/opacity`.

### D6. A 4–5px gap appears below an image.
`<img>` is inline, so it sits on the text baseline. Fix: `img { display: block; }` or `vertical-align: middle`.

### D7. A horizontal scrollbar appears on mobile.
Some element is wider than the viewport: `100vw` (includes the scrollbar width), a fixed width, negative margin, or a long word/URL. Debug with `* { outline: 1px solid red }` or find the widest element in JS. Fix: `max-width: 100%`, `overflow-wrap: anywhere`, use `100%` instead of `100vw`.

### D8. Hover gets stuck on mobile.
On touch devices the hover state stays after a tap. Fix: `@media (hover: hover) { .btn:hover {...} }`.

### D9. The parent height is 0 (floated children).
Floats are out of the flow. Fix: `display: flow-root`, a clearfix, or Flex/Grid.

### D10. An absolute child appears in the wrong place.
There is no positioned ancestor, so it is placed relative to the viewport/initial containing block. Give the parent `position: relative`.

### D11. A style does not override.
Specificity or order: check the strike-through in the DevTools Styles panel; raise the selector's specificity or fix the order / `@layer` (`!important` is the last resort); check for a typo or invalid value (invalid declarations are ignored).

### D12. Text jumps when the font loads (FOUT/CLS).
Use `font-display: swap` plus fallback metrics (`size-adjust`), preload the woff2, subset the font, or use `font-display: optional` if you want zero CLS.

### D13. Flex `gap` or auto margin is not right.
`margin-left: auto` pushes a flex item to the right (it absorbs extra space). `justify-content: space-between` with wrapping has a last-row alignment issue → use Grid or a spacer.

### D14. The animation is janky / low FPS.
Layout/paint properties are being animated. Fix: `transform/opacity`, temporary `will-change`, fewer big blurs/shadows, `contain`. DevTools: Performance → Frames, Rendering → Paint flashing / Layer borders.

### D15. A `100vh` section is cut by the address bar on mobile.
Use `dvh/svh` (Q65).

### D16. The same CSS works in Chrome but not in Safari.
Check caniuse (gap in flex, `:has`, `aspect-ratio`, `100dvh`), `-webkit-` prefixes (`-webkit-backdrop-filter`, `-webkit-line-clamp`), default styling of date/inputs, `position: sticky` in tables, and `overflow: clip`. Use Autoprefixer and a test matrix.

# 🎭 Part 8: Tricky / Gotcha Questions

### T1. A `%` padding/margin is relative to what?
**Both** (even top/bottom) are relative to the parent's **width**. That is why `padding-top: 56.25%` was the old aspect-ratio hack.

### T2. Why does `margin: auto` not center vertically in a normal block?
In block flow, a vertical auto margin is 0. It works for flex/grid items or absolute elements (`inset: 0`).

### T3. Why does `position: fixed` sometimes not stay fixed?
If an ancestor has `transform`, `filter`, `perspective`, `will-change: transform` or `contain: paint`, the element is positioned relative to that ancestor instead.

### T4. What are the side effects of `overflow: hidden`?
It creates a BFC (contains floats, stops margin collapse), breaks `position: sticky`, clips absolute children, and may clip the focus ring.

### T5. What is the output of `:nth-child(2)` vs `:nth-of-type(2)`?
```html
<div><h2>T</h2><p>A</p><p>B</p></div>
```
`p:nth-child(2)` → **A** (the 2nd child is a p). `p:nth-of-type(2)` → **B** (the 2nd p).

### T6. `line-height: 1.5` vs `150%` vs `1.5em`
Unitless = each child uses 1.5 × its own font-size (recommended). `%`/`em` are computed on the parent and the **fixed px value** is inherited (a child with a bigger font can overlap).

### T7. What is `rem` relative to? What if the user changes the browser font-size?
The root `html` font-size. The default is 16px, but a user setting can change it. So the `html { font-size: 62.5% }` hack is risky for accessibility (it overrides the user's preference). Better: keep `:root { font-size: 100% }` and do the `rem` math.

### T8. In media queries, `em` is relative to what?
The browser's **initial font-size** (not your root CSS). `em` breakpoints scale correctly with zoom and the user's font-size.

### T9. Why is there a gap between inline-block elements?
The whitespace in the HTML renders as one space character. Fix: use Flex, `font-size: 0` on the parent, HTML comments, or negative margin.

### T10. Can a child be visible when its parent is `visibility: hidden`?
Yes! `visibility` is inherited, but the child can set `visibility: visible` and show up (this is not possible with `display: none`).

### T11. Why does `a:hover` sometimes not work on a link?
Order: **LVHA** (`:link, :visited, :hover, :active`). With equal specificity, the later rule wins.

### T12. Is `* { margin: 0 }` a good idea?
It is simple and its specificity is 0, but it resets everything, including spacing that should be semantic, and can affect third-party widgets and form controls. Keep your modern reset targeted instead.

### T13. `max-width` vs `width` on an image?
`width: 100%` also upscales the image. `max-width: 100%; height: auto` only shrinks it and keeps the aspect ratio.

### T14. What are the use and risk of `display: contents`?
It removes the element's own box, and its children become items of the grandparent's grid/flex. Risk: older browsers had an accessibility bug (the role was lost), so avoid it on buttons and lists.

### T15. Why is `transition: all` bad?
It animates unexpected properties too (including layout properties), hurts performance, and gives surprising effects. List specific properties.

### T16. What is the reference for `top/left` percentages?
The containing block (the positioned ancestor, or the viewport for fixed). `translate(%)` is relative to the element's **own** size.

### T17. What is `currentColor`?
The value of the element's `color`. Useful for SVG and borders: `border: 1px solid currentColor; svg { fill: currentColor }`.

### T18. `all: unset` vs `revert`?
`unset` sends everything to inherit/initial (the browser's default styles also vanish, so a button loses its look). `revert` goes back to the user-agent stylesheet.

### T19. `background-attachment: fixed` on mobile?
It is buggy or disabled on iOS Safari. Alternatives: a `position: fixed` pseudo-element, or `sticky`.

### T20. Which wins at equal specificity? And with `@layer`?
Source order (the last one wins). With layers, **layer order** is checked first, then specificity; unlayered styles beat layered ones.

# 📚 Part 11: Complete Coverage (InterviewBit-style)

## 11A. Classic CSS Questions

### K1. What are the advantages and disadvantages of CSS?
Advantages: separation, reusability, caching, consistency, responsive design, animations. Disadvantages: global scope and collisions, cross-browser differences, specificity wars, (older) no variables, hard to debug in large codebases.

### K2. What are the new features of CSS3?
Rounded corners, shadows, gradients, transitions/animations, transforms, Flexbox/Grid, media queries, multi-column, web fonts (`@font-face`), opacity/RGBA, new selectors, variables, `calc()`, filters, `clip-path`, blend modes.

### K3. What are CSS Sprites?
Combining many small images into one image and showing the right part with `background-position`, so there are fewer HTTP requests. With HTTP/2 and SVG sprites this matters less today (now we use an SVG `<symbol>` sprite).

### K4. List of important pseudo-classes
`:hover :active :focus :focus-visible :focus-within :visited :link :target :root :empty :checked :disabled :enabled :required :optional :valid :invalid :in-range :first-child :last-child :only-child :nth-child() :nth-last-child() :first-of-type :nth-of-type() :not() :is() :where() :has() :dir() :lang()`.

### K5. List of pseudo-elements
`::before ::after ::first-letter ::first-line ::selection ::placeholder ::marker ::backdrop ::file-selector-button ::cue ::part() ::slotted()`.

### K6. What are the values of `visibility`?
`visible, hidden, collapse` (hides table rows/columns and frees the space), inherit.

### K7. What are the types of CSS units?
Absolute: `px, pt, pc, cm, mm, in`. Relative: `em, rem, %, vw, vh, vmin, vmax, ch, ex, lh`. Dynamic viewport: `dvh, svh, lvh`. Container: `cqw, cqh`. Time: `s, ms`. Angle: `deg, rad, turn`.


### K9. How do you make columns without `float`?
Flex, Grid, or `column-count`. Float is now used only for text wrapping.

### K10. `opacity` vs `rgba`/`transparent`?
`opacity` makes the whole element (children and text) transparent. `rgba` makes only that one color transparent. To protect the children, use an `rgba` background.

### K11. What is the `content` property?
It works only with `::before/::after/::marker`: a string, `attr()`, `counter()`, `url()`, `open-quote`.

### K12. `@import` vs `<link>` (again, performance angle)
`@import` creates a sequential waterfall; `<link>` is parallel. Sass `@use/@import` is resolved at compile time, so it has no such issue.

### K13. What is the `:root` selector?
The root element of the document (`html` in HTML, specificity `(0,1,0)`). Used for global CSS variables.

### K14. `box-shadow` syntax?
`offset-x offset-y blur spread color [inset]`. Multiple shadows are comma separated; layered shadows look more realistic.

### K15. How do you make an image responsive (CSS)?
`img { max-width: 100%; height: auto; display: block; }` + `object-fit` + HTML `srcset`.

### K16. `::selection`, `caret-color`, `accent-color`
```css

```

### K17. Vertical text / writing-mode
`writing-mode: vertical-rl; text-orientation: mixed;` (CJK, sidebars).

## 11B. Advanced / Modern CSS

### A1. `clip-path`, `mask`, `shape-outside`
`clip-path: circle(50%) | polygon() | inset()` cuts a shape. `mask-image` applies an alpha mask. `shape-outside` makes text wrap around a curve next to a float.

### A2. `mix-blend-mode`, `background-blend-mode`, `isolation`
Photoshop-like blending (`multiply, screen, overlay`). `isolation: isolate` limits blending to a group.

### A3. `scroll-margin`, `scroll-padding`, `overscroll-behavior`
Use `scroll-padding-top` so anchor links are not hidden under a sticky header. Stop scroll chaining inside a modal with `overscroll-behavior: contain`.

### A4. `text-wrap: balance | pretty`, `hyphens`, `overflow-wrap`
`balance` evens out heading lines, `pretty` reduces orphans. `word-break: break-all` vs `overflow-wrap: anywhere` (for long URLs).

### A5. Interactive UI with `:focus-within`, `:target`, `:checked`

### A6. Modern layout units and functions
`min-content / max-content / fit-content()`, `minmax()`, `repeat()`, `clamp()`, `round()`, `mod()`, trig functions `sin()/cos()`, `sibling-index()` (new).

### A7. Anchor positioning, popover, `@starting-style` (new)
`anchor-name` + `position-anchor` bind a tooltip/popover to its anchor (Chromium). The `popover` attribute + `::backdrop`. Use with progressive enhancement.

## 11C. HTML + CSS + JS Mixed

### M1. How do you change CSS from JS?
```js
el.classList.add('open');                // best: toggle a class
el.style.setProperty('--x', '10px');     // CSS variable
el.style.color = 'red';                  // inline (last resort)
getComputedStyle(el).getPropertyValue('width');   // final computed value
document.styleSheets[0].insertRule('.a{color:red}', 0);  // CSSOM
```
Best practice: **JS state → class/data-attribute, styling stays in CSS**.

### M2. `getComputedStyle` vs `element.style`
`element.style` has only **inline** styles. `getComputedStyle` gives the final resolved values (cascade + inheritance), is read-only, and can trigger a reflow.

### M3. Media queries in JS with `matchMedia`
```js
const mq = window.matchMedia('(prefers-color-scheme: dark)');
mq.addEventListener('change', (e) => setTheme(e.matches ? 'dark' : 'light'));
```

### M4. What is layout thrashing? How do you avoid it?
Interleaving reads (`offsetWidth`) and writes (`style.width`) in a loop forces a reflow every iteration. Fix: do all reads first, then all writes; use `requestAnimationFrame`; use `ResizeObserver`; use a library like `fastdom`.

### M5. CSS-driven state vs JS-driven state
Hover/focus/checked/open (`details[open]`, `:has()`) and `data-state="open"` attributes let CSS act as a state machine, so you need less JS and the behavior is declarative.

### M6. Theme toggle (complete)
```html
<button id="theme" aria-pressed="false">Dark</button>
<script>
  const root = document.documentElement;
  const saved = localStorage.getItem('theme');
  const sys = matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
  root.dataset.theme = saved ?? sys;
  theme.addEventListener('click', () => {
    const next = root.dataset.theme === 'dark' ? 'light' : 'dark';
    root.dataset.theme = next;
    localStorage.setItem('theme', next);
    theme.setAttribute('aria-pressed', next === 'dark');
  });
</script>
```

### M7. Animation end event / Web Animations API
```js
el.addEventListener('transitionend', () => el.remove(), { once: true });
el.animate([{ opacity: 0 }, { opacity: 1 }], { duration: 300, easing: 'ease-out', fill: 'forwards' });
```

### M8. `IntersectionObserver` + CSS (reveal on scroll)
```css
.reveal { opacity: 0; transform: translateY(20px); transition: .6s; }
.reveal.in { opacity: 1; transform: none; }
```
```js
new IntersectionObserver((es) => es.forEach(e => e.isIntersecting && e.target.classList.add('in'))).observe(el);
```

# 🧠 Part 12: Browser Internals & Performance

### B1. How does the browser process CSS?
Parse HTML → DOM. Parse CSS → **CSSOM**. DOM + CSSOM → **render tree** (`display:none` is excluded; `visibility:hidden` is included). **Style calculation** (cascade, inheritance, computed values) → **Layout** (geometry) → **Paint** (draw commands) → **Layerize + Composite** (GPU). CSS is **render-blocking** (the CSSOM is needed) and it can also block JS (a script waits for the CSSOM).

### B2. Cascade steps (priority order)
1. Origin and importance (transitions > `!important` UA > `!important` user > `!important` author > author animations > author normal > user > UA)
2. Context (Shadow DOM)
3. Style attribute (inline)
4. **Layers** (`@layer`)
5. **Specificity**
6. **Order of appearance**

### B3. Why does the browser match selectors right to left?
For `.nav ul li a`, the browser first finds all `a` elements, then checks the ancestor `li`... This rejects non-matches quickly. So keep the **key selector** (the rightmost one) specific; a broad or `*` rightmost part is costly.

### B4. Compositing layers and the GPU
Elements with `transform/opacity/will-change`, video or canvas become their own layer. A layer can move or fade on the GPU without re-layout or re-paint. Too many layers use more memory. DevTools → Layers panel.

### B5. FOUT, FOIT, FOUC
**FOUT** (fallback text shows, then swaps), **FOIT** (text is invisible until the font loads), **FOUC** (flash of unstyled content: CSS loaded late or injected by JS). Fix: `font-display`, preload, critical CSS, SSR style extraction.

### B6. How are CSS parsing errors handled?
An invalid declaration or selector is **ignored** (CSS is forgiving) and the rest of the rule works. An invalid selector in a list drops the whole rule (`:is()` is forgiving). This gives the fallback pattern: `width: 100%; width: min(100%, 60rem);`.

### B7. Paint flashing, Layer borders, Rendering tab (DevTools)
Rendering → Paint flashing (which areas repaint), Layout Shift Regions, FPS meter, Layer borders. Performance panel → Recalculate Style, Layout, Paint, Composite events.

### B8. Critical rendering metrics
FCP, LCP, CLS, INP, TBT, TTFB. CSS impact: render-blocking CSS raises FCP/LCP; font swaps affect CLS; heavy effects affect INP.

# 🧩 Part 14: Output-Based & Spot the Error

### O1. What color is the text?
```html
<style> p{color:red} .a{color:blue} #b{color:green} </style>
<p class="a" id="b" style="color:black">Ritesh</p>
```
**Black** (inline > id > class > element).

### O2. What is the gap between the two boxes?
```css
.a { margin-bottom: 30px; } .b { margin-top: 20px; }
```
**30px** (margin collapse, not 50).

### O3. What is the font-size?
```html
<style> html{font-size:16px} .a{font-size:2em} .b{font-size:2em} </style>
<div class="a"><div class="b">Hi</div></div>
```
`.a` = 32px, `.b` = 2 × 32 = **64px** (em compounds). With `rem` it would be 32px.

### O4. What is the total rendered width?
```css
.box { width: 200px; padding: 20px; border: 5px solid; }
```
content-box: **250px** · border-box: **200px**.

### O5. What is the parent's height?
```html
<div class="p" style="border:1px solid"><div style="float:left;height:100px"></div></div>
```
**About 0** (only the border). The float is out of the flow. Fix: `display: flow-root`.

### O6. Which element is on top?
```html
<div class="p1" style="position:relative; z-index:1"><div style="position:absolute; z-index:9999">A</div></div>
<div class="p2" style="position:relative; z-index:2">B</div>
```
**B is on top.** A's `9999` is only inside p1's stacking context, and p1 (1) < p2 (2).

### O7. Which paragraph turns red?
```css
p:nth-child(2) { color: red; }
```
```html
<div><h2>T</h2><p>One</p><p>Two</p></div>
```
**One** (the 2nd child of the div). With `nth-of-type(2)` it would be Two.

### O8. Which one is valid?
```css
width: calc(100%-20px);    /* ❌ */
width: calc(100% - 20px);  /* ✅ */
```
Spaces are required on both sides of `+` and `-`. They are not needed around `*` and `/`.

### O9. Which rule wins?
```css
.a .b { color: red; }       /* (0,2,0) */
div.b.c { color: blue; }    /* (0,2,1) */
```
For `<div class="a"><div class="b c">`, **blue** wins (it has an extra element selector).

### O10. Where does the absolute element appear?
```css
.child { position: absolute; }   /* no top/left given */
```
At its **static position** (where it would have been in the flow), but it leaves the flow and takes no space.

### O11. When does hover work?
```css
a:hover { color: red; } a:link { color: blue; }
```
`:link` comes later with the same specificity, so **blue wins and hover does not work** (the LVHA order is broken). Correct order: link, visited, hover, active.

### O12. What is the result?
```css
.box { width: 100px; height: 100px; transform: translateX(50px); }
```
It looks shifted 50px to the right, but **layout and space do not change** (neighbors stay where they are).

### O13. What is the height?
```css
.parent { height: auto; } .child { height: 100%; }
```
The child's `height: 100%` computes to **auto** (the parent has no explicit height).

### O14. Which declaration applies?
```css
.t { color: red; color: invalid-value; color: blue; }
```
`color: blue` (the invalid one is skipped). If the invalid one were last, red would apply.

### O15. What is the output?
```css
.card { display: flex; }
.card > * { flex: 1; }
```
Do the three children have equal width? **Yes** (`flex: 1` = `1 1 0%`), regardless of content size (but very long content may grow because of `min-width: auto`).

### Mistake 1: Using fixed `px` widths for layout
**❌ Wrong:**
```css
.container { width: 1200px; }
.card { width: 300px; height: 400px; }
```
**🤔 Why it is a problem:** On a phone (360px wide) the page scrolls sideways. On a big screen it looks small. A fixed `height` also cuts the content when the text is longer than you expected.

**✅ Correct:**
```css
.container { width: min(100% - 2rem, 1200px); margin-inline: auto; }
.cards { display: grid; grid-template-columns: repeat(auto-fit, minmax(260px, 1fr)); gap: 1rem; }
.card { min-height: 12rem; }   /* min-height, not height */
```
**💬 Say in the interview:** "I use flexible units, `max-width`, `min-height` and Grid/Flex so the layout adapts to any screen and any content length."

---

### Mistake 2: Styling with `!important` and `#id` selectors
**❌ Wrong:**
```css
#header .nav ul li a { color: red !important; }
```
**🤔 Why it is a problem:** The selector is so strong that to override it later, someone must write an even stronger selector or another `!important`. This is called a **specificity war**. The CSS becomes impossible to maintain.

**✅ Correct:**
```css
.nav-link { color: red; }          /* one class = low, flat specificity */
.nav-link--active { color: blue; } /* a modifier class, same strength, later in the file */
```
If you must override third-party CSS, put the third-party CSS in a low `@layer` instead of increasing specificity.

**💬 Say:** "I keep specificity flat and low. `!important` is only for utility classes or accessibility overrides."

---

### Mistake 3: Using `position: absolute` to build the page layout
**❌ Wrong:**
```css
.sidebar { position: absolute; left: 0; top: 80px; width: 250px; }
.content { position: absolute; left: 260px; top: 80px; }
```
**🤔 Why it is a problem:** Absolute elements leave the normal flow, so the parent does not know their height. The footer overlaps the content, and the layout breaks on small screens.

**✅ Correct:**
```css
.layout { display: grid; grid-template-columns: 250px 1fr; gap: 1rem; }
```
**💬 Say:** "Absolute positioning is for small overlays like badges and tooltips. Page layout is for Grid and Flexbox."

---

### Mistake 4: `z-index` inflation (`z-index: 99999`)
**❌ Wrong:**
```css
.modal { z-index: 99999; }
.dropdown { z-index: 999999; }
.toast { z-index: 9999999; }
```
**🤔 Why it is a problem:** Everyone keeps raising the number to win. Also, a big number does not work if the element is inside a **different stacking context** (for example a parent with `transform` or `opacity`).

**✅ Correct:**
```css
:root {
  --z-dropdown: 100;
  --z-modal: 200;
  --z-toast: 300;
}
.modal { z-index: var(--z-modal); }
.app-root { isolation: isolate; }   /* contains z-index inside this area */
```
**💬 Say:** "I keep z-index values in named tokens, and I understand stacking contexts instead of using bigger numbers."

---

### Mistake 5: Removing the focus outline (`outline: none`)
**❌ Wrong:**
```css
button:focus { outline: none; }
```
**🤔 Why it is a problem:** Keyboard users cannot see where they are on the page. This is an accessibility failure (WCAG).

**✅ Correct:**
```css
button:focus-visible { outline: 3px solid #4f46e5; outline-offset: 2px; }
```
`:focus-visible` shows the ring for keyboard focus, and hides it for mouse clicks, so the design stays clean.

**💬 Say:** "I never remove the outline without a better replacement, and I use `:focus-visible`."

---

### Mistake 6: `transition: all` and animating layout properties
**❌ Wrong:**
```css
.box { transition: all 0.3s; }
.box:hover { width: 320px; left: 20px; margin-top: 10px; }
```
**🤔 Why it is a problem:** `all` animates every property, even ones you did not plan. Animating `width`, `left`, `margin` forces the browser to recalculate layout on every frame, so the animation is janky (low FPS).

**✅ Correct:**
```css
.box { transition: transform 0.3s ease, opacity 0.3s ease; }
.box:hover { transform: translateY(-4px) scale(1.02); }
```
**💬 Say:** "I animate only `transform` and `opacity` because they run on the GPU without layout or paint."

---

### Mistake 7: Using `100vh` for full-screen sections on mobile
**❌ Wrong:**
```css
.hero { height: 100vh; }
```
**🤔 Why it is a problem:** On mobile, `100vh` is the biggest viewport (address bar hidden). When the address bar is visible, the bottom of the hero is cut off.

**✅ Correct:**
```css
.hero { min-height: 100vh; min-height: 100dvh; }  /* old browsers use the first line */
```
**💬 Say:** "I use `dvh` or `svh` units with a `vh` fallback for mobile."

---

### Mistake 8: Fixed `px` font sizes and `vw`-only font sizes
**❌ Wrong:**
```css
body { font-size: 14px; }
h1 { font-size: 5vw; }
```
**🤔 Why it is a problem:** `px` ignores the user's browser font-size setting (many people with weak eyesight increase it). A `vw`-only size does not grow when the user zooms in, and gets too small on phones and too big on wide screens.

**✅ Correct:**
```css
body { font-size: 1rem; }
h1 { font-size: clamp(1.75rem, 1rem + 3vw, 3rem); }  /* min, flexible, max */
```
**💬 Say:** "I use `rem` and `clamp()` so text respects user settings and scales smoothly."

---

### Mistake 9: Magic numbers instead of design tokens
**❌ Wrong:**
```css
.a { color: #4f46e5; padding: 13px; }
.b { color: #4f46e4; padding: 15px; }  /* almost the same color, by mistake */
```
**🤔 Why it is a problem:** Values are repeated and slightly different. Changing the brand color means searching the whole project. Dark mode is very hard.

**✅ Correct:**
```css
:root { --color-primary: #4f46e5; --space-2: 0.5rem; --space-4: 1rem; }
.a { color: var(--color-primary); padding: var(--space-4); }
```
**💬 Say:** "Design tokens give one source of truth, so theming and rebranding are easy."

---

### Mistake 10: Deep nesting and over-qualified selectors
**❌ Wrong:**
```css
body div.page section.content ul.list li.item a.link span.text { color: red; }
div.card { }   /* "div" is not needed */
```
**🤔 Why it is a problem:** The selector is tied to the exact HTML structure, so a small HTML change breaks it. It has high specificity and is hard to override.

**✅ Correct:**
```css
.item-text { color: red; }
.card { }
```
**💬 Say:** "I keep selectors short, usually one class, and I do not depend on the HTML structure."

---

### Mistake 11: Hiding content the wrong way (accessibility)
**❌ Wrong:**
```css
.label { display: none; }   /* you wanted screen readers to still read it */
```
**🤔 Why it is a problem:** `display: none` and `visibility: hidden` hide the content from screen readers too. And the opposite mistake: making something "invisible" with `opacity: 0` keeps it focusable, so keyboard users land on an invisible element.

**✅ Correct:**
```css
.sr-only {              /* hidden visually, still read by screen readers */
  position: absolute; width: 1px; height: 1px; margin: -1px; padding: 0;
  overflow: hidden; clip: rect(0 0 0 0); white-space: nowrap; border: 0;
}
```
Use `display: none` when the content should be hidden from everyone.

**💬 Say:** "I choose the hiding method by audience: everyone, visual users only, or screen readers only."

---

### Mistake 12: Hover-only interactions
**❌ Wrong:**
```css
.menu:hover .submenu { display: block; }   /* only mouse users can open it */
```
**🤔 Why it is a problem:** Touch devices have no real hover, and keyboard users cannot hover.

**✅ Correct:**
```css
.menu:hover .submenu,
.menu:focus-within .submenu { display: block; }

@media (hover: hover) { .btn:hover { background: #4338ca; } }
```
**💬 Say:** "Every hover effect must also work with focus and touch."

---

### Mistake 13: Desktop-first CSS with long override chains
**❌ Wrong:**
```css
.card { display: flex; padding: 3rem; width: 33%; }
@media (max-width: 1024px) { .card { width: 50%; padding: 2rem; } }
@media (max-width: 600px)  { .card { display: block; width: 100%; padding: 1rem; } }
```
**🤔 Why it is a problem:** You write rules and then cancel them. More CSS, more bugs, and phones (the most users) download and process extra work.

**✅ Correct:**
```css
.card { padding: 1rem; }                                    /* mobile first */
@media (min-width: 600px)  { .card { padding: 2rem; } }
@media (min-width: 1024px) { .card { display: flex; padding: 3rem; } }
```
**💬 Say:** "Mobile-first: base styles for small screens, then `min-width` queries add enhancements."

---

### Mistake 14: Images without dimensions or aspect ratio
**❌ Wrong:**
```html
<img src="hero.jpg" alt="Hero" />
```
**🤔 Why it is a problem:** The browser does not know the size until the image loads, so the page content jumps down. This is bad **CLS** (Cumulative Layout Shift) and hurts SEO and user experience.

**✅ Correct:**
```html
<img src="hero.jpg" alt="Hero" width="800" height="450" />
```
```css
img { max-width: 100%; height: auto; }
.thumb { aspect-ratio: 16 / 9; object-fit: cover; }
```
**💬 Say:** "I always reserve space for media with width/height or `aspect-ratio` to avoid layout shift."

---

### Mistake 15: Hard-coded colors that break dark mode
**❌ Wrong:**
```css
body { background: #ffffff; color: #111111; }
.card { background: #f5f5f5; }
```
**🤔 Why it is a problem:** To add dark mode you must edit every rule. You may also create low-contrast text that nobody can read.

**✅ Correct:**
```css
:root { color-scheme: light dark; --bg: #fff; --fg: #111; --surface: #f5f5f5; }
@media (prefers-color-scheme: dark) { :root { --bg: #0b0b0f; --fg: #eee; --surface: #1a1a22; } }
body { background: var(--bg); color: var(--fg); }
.card { background: var(--surface); }
```
Always check contrast: text needs at least 4.5:1.

**💬 Say:** "I build themes with CSS variables, so dark mode is a small change at the top, not a rewrite."

---

### Mistake 16: Writing vendor prefixes by hand
**❌ Wrong:**
```css
.box { -webkit-transition: all .3s; -moz-transition: all .3s; -o-transition: all .3s; transition: all .3s; }
```
**🤔 Why it is a problem:** It is noisy, easy to forget, and old prefixes stay in the code forever even when no longer needed.

**✅ Correct:** Write the standard property only, and let **Autoprefixer** (PostCSS) add what your `browserslist` needs.
```css
.box { transition: transform .3s; }
```
**💬 Say:** "I use Autoprefixer with a browserslist, so prefixes match our real supported browsers."

---

### Mistake 17: Fighting third-party CSS with higher and higher specificity
**❌ Wrong:**
```css
body .wrapper .lib-button.lib-button--primary { background: red !important; }
```
**🤔 Why it is a problem:** Every override needs a stronger selector. Updating the library can silently break your styles.

**✅ Correct:**
```css
@layer vendor, app;
@import url("lib.css") layer(vendor);          /* library goes in the low layer */
@layer app { .lib-button { background: red; } } /* your CSS wins automatically */
```
**💬 Say:** "Cascade layers let my styles win by order, not by specificity tricks."

---

### Mistake 18: Using margins instead of `gap`, and `float` for layout
**❌ Wrong:**
```css
.item { float: left; margin-right: 16px; }
.item:last-child { margin-right: 0; }
```
**🤔 Why it is a problem:** You need special rules for the first/last item, floats collapse the parent's height, and wrapping gets messy.

**✅ Correct:**
```css
.row { display: flex; flex-wrap: wrap; gap: 1rem; }
```
**💬 Say:** "`gap` spaces items only *between* them, so I do not need first-child/last-child fixes."

---

### Mistake 19: Forgetting `box-sizing: border-box`
**❌ Wrong:**
```css
.input { width: 100%; padding: 12px; border: 1px solid #ccc; }  /* overflows its parent */
```
**🤔 Why it is a problem:** With the default `content-box`, the padding and border are added **on top of** `width: 100%`, so the element becomes wider than the parent.

**✅ Correct:**
```css
*, *::before, *::after { box-sizing: border-box; }
```
**💬 Say:** "I set `border-box` globally so width means the final visible width."

---

### Mistake 20: Using `px` or `%` for `line-height`
**❌ Wrong:**
```css
p { line-height: 24px; }   /* or 150% */
```
**🤔 Why it is a problem:** A fixed or percentage line-height is calculated on the parent and the final number is inherited. A child with a bigger font can get lines that overlap.

**✅ Correct:**
```css
body { line-height: 1.6; }  /* unitless: every element uses its own font-size × 1.6 */
```
**💬 Say:** "I always use a unitless `line-height`."

# 🎯 Part 17: Signals That Show You Are Really Experienced

> **What should you do?** Practice answering in the "Strong" style below. Use the same style for every topic.

### Signal 1: You have a clear mental model of the cascade
| | Example answer |
|---|---|
| ❌ Weak | "Specificity means ID is stronger than class." |
| ✅ Strong | "The browser decides a winner in this order: origin and importance, then inline, then **cascade layer**, then **specificity**, then **source order**. So a rule in a later layer can beat a more specific rule in an earlier layer. I keep specificity flat so source order and layers do the work." |
**Prove it:** mention `@layer`, `:where()` (zero specificity), and stacking contexts.

I also cut CSS from 180 KB to 60 KB using the Coverage tab." |

# ⚡ Part 18: Cheat Sheet & Last-Minute Revision

> **What is this part?** A quick page to read **1 hour before the interview**. Everything here is explained in detail earlier in the file.

## 18.1 Starter reset (copy this in every project)
```css
*, *::before, *::after { box-sizing: border-box; }
body { margin: 0; line-height: 1.6; font-family: system-ui, sans-serif; }
img, video { max-width: 100%; height: auto; display: block; }
button, input, select, textarea { font: inherit; }
:focus-visible { outline: 3px solid #4f46e5; outline-offset: 2px; }
@media (prefers-reduced-motion: reduce) { * { animation: none !important; transition: none !important; } }
```

## 18.2 Which layout tool do I use?
| Need | Use |
|---|---|
| Items in one row or one column (navbar, buttons) | **Flexbox** |
| Rows and columns together (page, card grid) | **Grid** |
| Center one thing | `display:grid; place-items:center` |
| Overlay on top of something (badge, tooltip) | `position: absolute` inside `position: relative` |
| Header that stays on top while scrolling | `position: sticky; top: 0` |
| Text wrapping around an image | `float` (rare today) |
| Columns of text / masonry | `column-count` |

## 18.3 Units: what to use
| Use for | Unit |
|---|---|
| Font size, spacing | `rem` |
| Component-relative spacing | `em` |
| Borders, hairlines | `px` |
| Full-screen height on mobile | `dvh` |
| Fluid text | `clamp(min, preferred, max)` |
| Width of text blocks | `ch` (like `max-width: 65ch`) |

## 18.4 Specificity in 10 seconds
`inline` > `#id` (1,0,0) > `.class / [attr] / :hover` (0,1,0) > `element / ::before` (0,0,1). Same strength → the **later** rule wins. `:where()` = 0. Layers are checked **before** specificity.

## 18.5 z-index in 10 seconds
Works only on positioned (or flex/grid) items. Compared only **inside its stacking context**. New contexts come from `transform`, `opacity < 1`, `filter`, `position + z-index`, `isolation: isolate`, `will-change`.

## 18.6 Animation rules
- Animate only `transform` and `opacity`.
- Never `transition: all`.
- Use `will-change` only when needed, and remove it later.
- Respect `prefers-reduced-motion`.
- `height: auto` → use `grid-template-rows: 0fr → 1fr`.

## 18.7 Responsive checklist
- [ ] `<meta name="viewport" content="width=device-width, initial-scale=1">`
- [ ] Mobile-first (`min-width` queries)
- [ ] Breakpoints chosen by content
- [ ] Images: `max-width: 100%`, width/height or `aspect-ratio`
- [ ] No horizontal scroll at 320px
- [ ] Touch targets at least 44×44px
- [ ] Test with browser zoom 200%

## 18.8 Accessibility checklist
- [ ] Visible `:focus-visible` outline
- [ ] Contrast ≥ 4.5:1 (text), 3:1 (large text / UI)
- [ ] Do not rely on color only
- [ ] Reduced motion and dark mode respected
- [ ] Hidden text for screen readers uses `.sr-only`, not `display:none`

## 18.9 Performance checklist
- [ ] Critical CSS inline, the rest async
- [ ] Unused CSS removed (Coverage tab / PurgeCSS)
- [ ] Fonts: `font-display: swap`, preload woff2
- [ ] No layout-triggering animations
- [ ] `content-visibility: auto` for long pages
- [ ] Brotli + long cache with hashed file names

## 18.10 Debugging table (symptom → likely cause → fix)
| Symptom | Likely cause | Fix |
|---|---|---|
| `z-index` has no effect | Not positioned, or another stacking context | `position: relative`; check parent `transform/opacity`; `isolation: isolate` |
| Flex item overflows | `min-width: auto` | `min-width: 0` |
| `height: 100%` not working | Parent has no height | `min-height: 100dvh` or Grid/Flex |
| Sticky not sticking | Ancestor `overflow` / no `top` | Remove overflow; set `top` |
| Parent has 0 height | Floated children | `display: flow-root` |
| Gap under an image | Image is inline | `img { display: block }` |
| Sideways scroll on mobile | Something wider than the viewport (`100vw`, fixed width) | `max-width: 100%`; find the widest element |
| Style not applied | Lower specificity / typo / invalid value | Check strike-through in DevTools |
| Animation janky | Animating layout properties | Use `transform/opacity` |
| Text jumps on load | Font swap | `size-adjust`, preload, `font-display` |

## 18.11 30-second answers to the most common questions
- **Box model?** Content, padding, border, margin. With `border-box`, width includes padding and border.
- **Flex vs Grid?** Flex is 1-D and content-driven. Grid is 2-D and layout-driven. I use both together.
- **Specificity?** Inline > id > class > element; same strength → later wins; layers come first.
- **`em` vs `rem`?** `em` is relative to the element's font-size and compounds. `rem` is relative to the root.
- **Why does z-index fail?** It needs a positioned element and works only inside its stacking context.
- **Reflow vs repaint?** Reflow recalculates layout (expensive). Repaint redraws pixels. Composite only moves layers. Animate `transform/opacity`.
- **Margin collapse?** Adjacent vertical margins combine into the larger one. Not in flex/grid or a BFC.
- **Mobile-first?** Base styles for small screens, then `min-width` queries.
- **CSS variables vs Sass variables?** CSS variables are runtime and cascade. Sass variables are compile-time.
- **How do you center a div?** `display:grid; place-items:center`.

## 18.12 Last-minute checklist before the interview
- [ ] I can explain the box model, specificity, stacking context and BFC in my own words.
- [ ] I can write a centered layout, a responsive card grid and a sticky header from memory.
- [ ] I have 2 performance stories with numbers.
- [ ] I have 1 accessibility story and 1 architecture story (tokens / migration).
- [ ] I know the trade-offs of Tailwind vs CSS Modules vs CSS-in-JS.
