# 🟢 Part 1: Fresher (0–1 year)

### Q1. What is cloud computing and AWS? *(Must-know)*
On-demand delivery of compute, storage, databases and services over the internet with pay-as-you-go pricing. **AWS** is Amazon's cloud platform with 200+ services across global regions. Models: IaaS (EC2), PaaS (Elastic Beanstalk, RDS), SaaS, serverless (Lambda). Benefits: elasticity, speed, global reach, no upfront hardware.

### Q2. Regions, Availability Zones and Edge locations *(Must-know)*
A **Region** is a geographic area (e.g., `ap-south-1` Mumbai) with multiple isolated **Availability Zones** (one or more data centers each, connected by low-latency links). **Edge locations/PoPs** serve CloudFront/Route 53/Global Accelerator. Design across ≥2 AZs for high availability; choose regions by latency, compliance, price and service availability.

### Q3. Shared responsibility model *(Must-know)*
AWS secures the cloud (hardware, facilities, hypervisor, managed service internals). You secure what you put **in** the cloud (data, IAM, OS patching on EC2, network config, application security, encryption choices). Responsibility shifts with the service type (more with EC2, less with Lambda/S3).

### Q4. AWS account basics
Root user (use only for a few tasks; enable MFA, no access keys), IAM users/roles, billing and budgets, AWS Organizations for multi-account, regions enabled by default, service quotas. Use separate accounts for prod/non-prod.

### Q5. IAM fundamentals *(Must-know)*
**Users**, **groups**, **roles** (assumed temporarily, no long-term credentials), **policies** (JSON permissions). Evaluation: explicit Deny > explicit Allow > implicit Deny. Principle of least privilege; use roles for services and cross-account access; MFA for humans; prefer IAM Identity Center (SSO) over IAM users.
```json
{ "Version": "2012-10-17",
  "Statement": [{ "Effect": "Allow", "Action": ["s3:GetObject"], "Resource": "arn:aws:s3:::my-bucket/reports/*" }] }
```

### Q6. IAM policy types
Identity-based (attached to users/roles/groups), resource-based (S3 bucket policy, KMS key policy, trust policy), permissions boundaries, Service Control Policies (SCPs, org-level guardrails), session policies. Effective permissions = intersection of boundaries/SCPs and allows.

### Q7. EC2 basics *(Must-know)*
Virtual servers. Choose AMI, instance type (family: `t` burstable, `m` general, `c` compute, `r` memory, `i` storage, `g/p` GPU), key pair or SSM Session Manager, security groups, subnet, EBS volumes, IAM instance profile, user data. Purchasing: On-Demand, Reserved/Savings Plans, Spot, Dedicated.

### Q8. Security groups vs NACLs *(Must-know)*
| | Security Group | Network ACL |
|---|---|---|
| Level | Instance/ENI | Subnet |
| State | Stateful | Stateless |
| Rules | Allow only | Allow and deny, ordered |
| Default | Deny inbound, allow outbound | Allow all (default NACL) |

### Q9. VPC fundamentals *(Must-know)*
Private virtual network with CIDR (e.g., 10.0.0.0/16), subnets per AZ, route tables, Internet Gateway (public access), NAT Gateway (outbound for private subnets), VPC endpoints (private access to AWS services), security groups/NACLs. Public subnet = route to IGW; private subnet = no direct IGW route.

### Q10. Typical 3-tier VPC
Public subnets (ALB, NAT), private app subnets (EC2/ECS/EKS), private data subnets (RDS/ElastiCache) across ≥2 AZs. Security groups chain: ALB SG → app SG → DB SG.

### Q11. S3 basics *(Must-know)*
Object storage with buckets and keys; 11 nines durability; storage classes: Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier Instant/Flexible/Deep Archive. Features: versioning, lifecycle rules, replication (CRR/SRR), encryption (SSE-S3, SSE-KMS), presigned URLs, static website hosting, event notifications. Block Public Access on by default; bucket policies for access.

### Q12. S3 consistency and limits
Strong read-after-write consistency for all operations. Object max 5 TB; multipart upload for >100 MB (required >5 GB). Prefix request rates scale (3,500 writes/5,500 reads per prefix per second). Use CloudFront/Transfer Acceleration for global access.

### Q13. EBS vs Instance store vs EFS
EBS: persistent block storage per AZ (gp3, io2, st1, sc1), snapshots to S3. Instance store: ephemeral local disks (lost on stop/terminate). EFS: managed NFS, multi-AZ, shared across instances (Linux). FSx for Windows/Lustre/NetApp.

### Q14. RDS and Aurora
Managed relational DBs (MySQL, PostgreSQL, MariaDB, Oracle, SQL Server). Multi-AZ for HA (synchronous standby, automatic failover), read replicas for scale (async), automated backups + PITR, parameter groups, encryption with KMS. **Aurora**: cloud-native storage across 3 AZs (6 copies), up to 15 replicas, faster failover, Serverless v2. See `../04_Database/`.

### Q15. DynamoDB basics
Serverless key-value/document NoSQL: partition key (+ sort key), on-demand or provisioned capacity, GSIs/LSIs, TTL, streams, DAX cache, global tables, transactions. Model access patterns first; avoid scans and hot partitions.

### Q16. Lambda basics *(Must-know)*
Event-driven serverless functions: pay per invocation and duration, scale automatically, up to 15 min timeout, memory 128 MB–10 GB (CPU scales with memory), triggers (API Gateway, S3, SQS, EventBridge, DynamoDB streams). Concepts: cold starts, concurrency limits, layers, versions/aliases, environment variables, execution role, VPC attachment.
```js
export const handler = async (event) => ({ statusCode: 200, body: JSON.stringify({ message: "Hello Ritesh Kumar" }) });
```

### Q17. API Gateway
Managed API front door: REST, HTTP and WebSocket APIs; auth (IAM, Cognito, Lambda authorizers, JWT), throttling, caching, stages, usage plans, request validation, integration with Lambda/HTTP/AWS services. HTTP APIs are cheaper/faster; REST APIs have more features.

### Q18. Load balancers
ALB (L7, HTTP/HTTPS, path/host routing, WebSockets, gRPC), NLB (L4, ultra-low latency, static IPs, TLS passthrough), GWLB (appliances), CLB (legacy). Target groups, health checks, cross-zone balancing, sticky sessions, WAF integration on ALB.

### Q19. Auto Scaling
EC2 Auto Scaling groups with launch templates, min/max/desired, scaling policies (target tracking, step, scheduled, predictive), health checks, lifecycle hooks, instance refresh, mixed instances/Spot. Pair with ALB.

### Q20. Route 53
DNS service: record types (A, AAAA, CNAME, ALIAS, MX, TXT), routing policies (simple, weighted, latency, failover, geolocation, multivalue), health checks, private hosted zones. ALIAS records map apex domains to AWS resources free of query charges.

### Q21. CloudFront
CDN with edge caching, origins (S3, ALB, custom), behaviors, TTLs, invalidations, signed URLs/cookies, OAC for S3, WAF, Lambda@Edge/CloudFront Functions, HTTP/2/3, TLS via ACM (certs for CloudFront in `us-east-1`).

### Q22. CloudWatch, CloudTrail and Config
CloudWatch: metrics, logs, alarms, dashboards, Logs Insights, EventBridge integration. CloudTrail: API activity audit (who did what). AWS Config: resource configuration history and compliance rules. Use all three for operations and security.

### Q23. SQS, SNS, EventBridge
SQS (queue; standard vs FIFO), SNS (pub/sub fan-out), EventBridge (event bus with rules, schema registry, SaaS integrations, scheduler). See `../03_Backend/038_Message-Queues.md`.

### Q24. KMS and encryption
Customer-managed keys (CMKs) and AWS-managed keys; envelope encryption; key policies + IAM; automatic rotation; encryption at rest for S3/EBS/RDS/DynamoDB and TLS in transit via ACM. CloudHSM for dedicated HSMs.

### Q25. Secrets Manager vs Parameter Store
Secrets Manager: secrets with automatic rotation (RDS integration), cross-region replication, higher cost. SSM Parameter Store: config/secret storage (SecureString), cheaper, no native rotation. Fetch at runtime via IAM roles; never hard-code.

### Q26. Elastic Beanstalk, App Runner, Lightsail
Beanstalk: PaaS for web apps (EC2-based); App Runner: containers/source to HTTPS service with autoscaling; Lightsail: simple VPS bundles. Good for quick starts; more control needs ECS/EKS/EC2.

### Q27. Containers on AWS
ECR (registry), ECS (AWS-native orchestrator; EC2 or Fargate launch types), EKS (managed Kubernetes), App Runner. Fargate removes node management. See `045_Docker.md`, `046_Kubernetes.md`.

### Q28. Pricing basics
Pay for compute time, storage, requests and data transfer (egress costs; inbound free; cross-AZ/region charged). Free tier, Savings Plans/RIs, Spot (up to 90% off), right-sizing, Budgets and Cost Explorer. NAT Gateway and data transfer are common surprise costs.

### Q29. Well-Architected Framework pillars *(Must-know)*
Operational Excellence, Security, Reliability, Performance Efficiency, Cost Optimization, Sustainability. Use reviews and the Well-Architected Tool to find risks.

### Q30. AWS CLI and SDKs
```bash
aws configure sso
aws s3 cp report.pdf s3://my-bucket/reports/ --sse aws:kms
aws ec2 describe-instances --query 'Reservations[].Instances[].{id:InstanceId,state:State.Name}'
aws sts get-caller-identity
```
Use named profiles/SSO, `--region`, `--dry-run` where available, and avoid long-lived access keys.

# 🔵 Part 2: Junior (1–3 years)

### Q31. IAM roles in practice *(Must-know)*
Roles have a trust policy (who can assume) and permission policies (what they can do). EC2 instance profiles, Lambda execution roles, ECS task roles, EKS IRSA/Pod Identity, cross-account roles via `sts:AssumeRole`, GitHub OIDC roles. Short-lived credentials via STS replace access keys.
```json
{ "Effect": "Allow", "Principal": { "Federated": "arn:aws:iam::123456789012:oidc-provider/token.actions.githubusercontent.com" },
  "Action": "sts:AssumeRoleWithWebIdentity",
  "Condition": { "StringLike": { "token.actions.githubusercontent.com:sub": "repo:acme/app:ref:refs/heads/main" } } }
```

### Q32. IAM policy debugging
Use IAM Policy Simulator, Access Analyzer (unused access, external access), CloudTrail error codes (`AccessDenied` with `explicit deny` vs implicit), condition keys (`aws:SourceVpce`, `aws:PrincipalOrgID`, MFA), and check SCPs/permission boundaries/resource policies together.

### Q33. VPC networking in depth *(Must-know)*
Route tables: `0.0.0.0/0 → igw` (public), `→ nat` (private egress), local route for VPC CIDR. Subnet CIDRs (AWS reserves 5 IPs/subnet). **Gateway endpoints** (S3, DynamoDB; free, route-table based) and **interface endpoints** (PrivateLink; ENIs, per-hour cost). **VPC peering** (non-transitive, no overlapping CIDRs), **Transit Gateway** (hub-and-spoke), **Direct Connect/VPN** for hybrid, **PrivateLink** to expose services privately.

### Q34. NAT Gateway cost and alternatives
Per-hour + per-GB charges; per-AZ for resilience. Reduce with S3/DynamoDB gateway endpoints, interface endpoints for heavy services, VPC endpoints for ECR, egress-only IGW for IPv6, NAT instances for dev, and avoiding unnecessary internet egress.

### Q35. IPv6, DNS and DHCP in VPC
Dual-stack VPCs, egress-only internet gateways, Route 53 Resolver (inbound/outbound endpoints for hybrid DNS), `enableDnsSupport/Hostnames`, private hosted zones. Plan CIDRs to avoid overlap with on-prem and other VPCs.

### Q36. EC2 deep dive
Nitro system, EBS-optimized, enhanced networking, placement groups (cluster/spread/partition), instance metadata (IMDSv2 required), user data/cloud-init, AMI lifecycle (EC2 Image Builder), burstable credits (T-family), Graviton (ARM) for price-performance, Spot interruption handling (2-minute notice).

### Q37. Purchasing options & Savings Plans
On-Demand (flex), Savings Plans (Compute/EC2 instance commitments for $/hour), Reserved Instances (legacy-ish), Spot (interruptible), Capacity Reservations. Combine: baseline via Savings Plans, burst via On-Demand/Spot.

### Q38. EBS performance and snapshots
gp3 (baseline 3,000 IOPS/125 MB/s, independently tunable), io2 Block Express for high IOPS, throughput-optimized st1; snapshots are incremental, can be copied cross-region, encrypted; use Data Lifecycle Manager for automation; restore-time lazy loading (fast snapshot restore).

### Q39. S3 security *(Must-know)*
Block Public Access, bucket policies/IAM least privilege, ACLs disabled (Bucket owner enforced), SSE-KMS with bucket keys, VPC endpoint policies, Object Lock (WORM), MFA delete, access logs/CloudTrail data events, Macie for sensitive data discovery, presigned URLs with short expiry, CloudFront OAC to keep buckets private.

### Q40. S3 performance & design
Parallelize multipart uploads, byte-range fetches, avoid sequential key hot spots (modern S3 handles prefixes well), use S3 Transfer Acceleration or CloudFront for global clients, S3 Select/Athena for querying, Intelligent-Tiering for unknown access, lifecycle to Glacier, Inventory/Storage Lens for analytics.

### Q41. RDS operations
Multi-AZ failover (60-120 s), read replicas (cross-region possible), parameter/option groups, maintenance windows, Performance Insights, Enhanced Monitoring, RDS Proxy (connection pooling for Lambda), storage autoscaling, snapshots/PITR, encryption cannot be toggled in place (restore from snapshot copy), IAM auth.

### Q42. Aurora features
Shared storage volume, fast crash recovery, backtrack (MySQL), Global Database (cross-region <1 s lag), Serverless v2 (fine-grained scaling), Limitless/I/O-Optimized options (verify), cloning. Understand cluster vs reader endpoints.

### Q43. DynamoDB modeling *(Must-know)*
Single-table design vs multiple tables, partition key choice for even distribution, composite keys for queries, GSIs for alternative access patterns, sparse indexes, adjacency lists, TTL, conditional writes for concurrency, transactions (limited items), capacity modes (on-demand vs provisioned + autoscaling), item size limit 400 KB. See `../04_Database/030_MongoDB.md` for document modelling comparisons.

### Q44. ElastiCache
Managed Redis/Valkey/Memcached: caching, sessions, leaderboards, rate limiting; cluster mode, replicas, Multi-AZ failover, encryption in transit/at rest, parameter groups. See `../04_Database/031_Redis-and-Caching.md`.

### Q45. Lambda in depth *(Must-know)*
Execution environment lifecycle (init → invoke → freeze → reuse), cold starts (mitigate: smaller packages, provisioned concurrency, SnapStart for Java, ARM), concurrency (reserved vs provisioned, account limit), retries (async invocations retry twice; DLQ/on-failure destinations), idempotency (Powertools), `/tmp` storage (512 MB–10 GB), container image support, layers, environment variables with KMS, VPC access via Hyperplane ENIs.

### Q46. Lambda event sources
Sync (API Gateway, ALB, Function URL), async (S3, SNS, EventBridge), poll-based (SQS, Kinesis, DynamoDB Streams, MSK) with batch size, batching window, partial batch response, parallelization factor, bisect on error. Use reserved concurrency to protect downstreams.

### Q47. Step Functions
Serverless workflow orchestration (state machines in ASL): Task, Choice, Parallel, Map, Wait, Retry/Catch; Standard (long-running, exactly-once) vs Express (high-volume, at-least-once); service integrations (SDK, optimized), callbacks with task tokens. Use for sagas and multi-step processes.

### Q48. SQS/SNS/EventBridge patterns
Fan-out (SNS → SQS), buffering spikes (SQS between API and workers), DLQs with redrive, FIFO for ordering, EventBridge rules with content filtering and cross-account buses, Scheduler for cron/one-time jobs, Pipes for point-to-point integrations.

### Q49. Kinesis vs MSK vs SQS
Kinesis Data Streams (managed, shards, ordered per shard, replay up to 365 days), Firehose (delivery to S3/Redshift/OpenSearch), MSK (managed Kafka), SQS (queue without replay). Choose by ordering/replay/throughput and ecosystem needs.

### Q50. ECS vs EKS vs Lambda vs EC2 *(Must-know)*
| Need | Choice |
|---|---|
| Simple containers, less ops, AWS-native | ECS on Fargate |
| Kubernetes ecosystem/portability | EKS |
| Event-driven, spiky, short tasks | Lambda |
| Full control, special hardware | EC2 |
| Quick web app from source/container | App Runner |

### Q51. ECS concepts
Cluster, task definition (containers, CPU/memory, roles, logging), service (desired count, load balancer, deployment strategy: rolling, blue/green via CodeDeploy), task role vs execution role, Service Connect/Cloud Map for discovery, capacity providers (Fargate/Fargate Spot/EC2 ASG), Exec for debugging.

### Q52. EKS essentials
Managed control plane, node options (managed node groups, Karpenter, Fargate), IRSA/Pod Identity, VPC CNI (pod IPs from VPC; IP exhaustion planning), add-ons (CoreDNS, kube-proxy, EBS/EFS CSI), AWS Load Balancer Controller, cluster autoscaling, upgrade cadence. See `046_Kubernetes.md`.

### Q53. CloudFormation, CDK and Terraform
CloudFormation: declarative templates/stacks, change sets, drift detection, StackSets; CDK: code (TypeScript/Python) synthesizing CloudFormation; Terraform: multi-cloud HCL with state. Use IaC for everything, modules/constructs for reuse. See `051_Terraform-and-IaC.md`.

### Q54. Systems Manager (SSM)
Session Manager (shell without SSH/bastion), Run Command, Patch Manager, Parameter Store, Automation runbooks, Inventory, State Manager. Eliminates inbound SSH ports and key management.

### Q55. Observability on AWS
CloudWatch metrics (custom with EMF), Logs Insights queries, alarms (composite, anomaly detection), X-Ray/ADOT for tracing, Container Insights, Contributor Insights, Synthetics canaries, managed Prometheus/Grafana. See `052_Monitoring-and-Observability.md`.

### Q56. Security services overview
GuardDuty (threat detection), Security Hub (aggregated findings/standards), Inspector (vulnerability scanning), Macie (S3 data discovery), Detective, WAF (L7 rules), Shield (DDoS), Firewall Manager, Network Firewall, Audit Manager, IAM Access Analyzer, Config rules, CloudTrail Lake.

### Q57. AWS Organizations and multi-account strategy *(Must-know)*
Separate accounts for environments, workloads, security (log archive, audit), shared services, sandbox. Use SCPs as guardrails, Control Tower landing zone, IAM Identity Center for SSO, centralized logging/security tooling, consolidated billing, tagging policies. Accounts are the strongest isolation boundary.

### Q58. Tagging and cost allocation
Standard tags (`owner`, `env`, `cost-center`, `app`), enforced via tag policies/Config rules/IaC modules; activate cost allocation tags; use Cost Explorer, CUR + Athena, Budgets with alerts, anomaly detection.

### Q59. Backup and recovery
AWS Backup (policies across EBS/RDS/DynamoDB/EFS/S3), cross-region/account copies, Vault Lock, PITR for RDS/DynamoDB, S3 versioning + replication, tested restores. Define RPO/RTO per workload.

### Q60. Disaster recovery strategies *(Must-know)*
| Strategy | RTO/RPO | Cost |
|---|---|---|
| Backup & restore | Hours / hours | Lowest |
| Pilot light | Tens of minutes / minutes | Low |
| Warm standby | Minutes / seconds-minutes | Medium |
| Multi-site active-active | Near zero | Highest |

# 🟡 Part 3: Mid (3–5 years)

### Q61. Designing highly available architectures *(Must-know)*
Multi-AZ everywhere: ALB across AZs, ASG spanning AZs, RDS Multi-AZ/Aurora, multi-AZ ElastiCache, S3/DynamoDB (inherently multi-AZ), stateless app tier, health checks and auto-healing, no single-AZ dependencies (NAT per AZ, endpoints per AZ). Test failure by terminating instances/AZ-level fault injection (FIS).

### Q62. Scalability patterns
Horizontal scaling behind ALB, caching (CloudFront, ElastiCache, DAX), async decoupling (SQS), read replicas, partitioning (DynamoDB keys, sharding), serverless scaling (Lambda, Aurora Serverless, DynamoDB on-demand), autoscaling on custom metrics (queue depth), and load testing to find limits.

### Q63. Security architecture baseline
Multi-account with SCPs, centralized CloudTrail/Config/GuardDuty/Security Hub, IAM Identity Center + MFA, no long-lived keys, private subnets for workloads, VPC endpoints, encryption by default (KMS), WAF on edges, least-privilege roles, secrets in Secrets Manager, patching via SSM/immutable AMIs, incident response runbooks.

### Q64. Network security patterns
Defense in depth: WAF/Shield at edge, ALB in public subnets only, app/data private, security groups referencing SGs, NACLs for coarse blocks, Network Firewall/Gateway LB for inspection, egress controls via proxies/endpoint policies, Flow Logs/Traffic Mirroring for visibility, PrivateLink for service exposure.

### Q65. Hybrid connectivity
Site-to-Site VPN (quick, IPsec over internet), Direct Connect (dedicated, consistent latency; use VPN as backup; LAGs, Direct Connect Gateway/Transit VIF), Transit Gateway for scalable routing, BGP, overlapping CIDR handling (PrivateLink/NAT), Route 53 Resolver endpoints for DNS.

### Q66. Cross-account access patterns
Role assumption with trust policies and external IDs for third parties, resource policies (S3, KMS, SQS), RAM sharing (subnets, TGW, Resolver rules), organization-wide conditions (`aws:PrincipalOrgID`), centralized logging buckets with write-only access.

### Q67. KMS design
Key policies are primary (plus grants); separate keys by data classification/environment; key rotation; multi-region keys for DR; use encryption context for auditing; avoid sharing keys across unrelated accounts; understand quotas and throttling (bucket keys reduce S3-KMS calls).

### Q68. Event-driven architecture on AWS
Producers emit events to EventBridge/SNS/SQS/Kinesis; consumers (Lambda, ECS, Step Functions) react; idempotency and DLQs; schema registry; event replay (EventBridge archive); choreography vs orchestration (Step Functions). See `../03_Backend/039_Microservices.md`.

### Q69. Serverless web app reference
CloudFront + S3 (frontend) → API Gateway/Lambda (APIs) → DynamoDB/Aurora Serverless; Cognito for auth; EventBridge/SQS for async; Step Functions for workflows; WAF; X-Ray/CloudWatch; IaC via CDK/SAM. Considerations: cold starts, limits (timeouts, payload size), vendor lock-in, observability.

### Q70. Container platform reference
ECR → ECS/Fargate or EKS; ALB with path routing; private subnets; Secrets Manager injection; CloudWatch Container Insights; autoscaling (target tracking); blue/green with CodeDeploy; CI via GitHub Actions + OIDC. See `047_CI-CD-and-DevOps.md`.

### Q71. Data lake & analytics
S3 data lake with Glue catalog/ETL, Lake Formation permissions, Athena (serverless SQL), Redshift (warehouse/Serverless), EMR (Spark/Hadoop), Kinesis/MSK ingestion, QuickSight BI, partitioning/Parquet for cost and speed. See `../10_AI_and_ML/075_Data-Engineering.md`.

### Q72. Database selection on AWS
RDS/Aurora (relational), DynamoDB (key-value at scale), DocumentDB (MongoDB-compatible), ElastiCache/MemoryDB (in-memory), Neptune (graph), Timestream (time series), Keyspaces (Cassandra), OpenSearch (search/log analytics), Redshift (OLAP), QLDB (deprecated; verify). Choose by access patterns, consistency, scale, ops.

### Q73. Cost optimization techniques *(Must-know)*
Right-size (Compute Optimizer), Savings Plans/RIs, Spot for stateless/batch, Graviton, autoscaling and scheduled shutdown for non-prod, S3 lifecycle/Intelligent-Tiering, delete unattached EBS/EIPs/old snapshots, reduce NAT/data transfer (endpoints, CloudFront, same-AZ traffic), Lambda memory tuning (Power Tuning), log retention limits, budgets + anomaly detection.

### Q74. Data transfer costs
Free: inbound, same-AZ private IP traffic; paid: cross-AZ, cross-region, internet egress, NAT processing. Architect to keep chatty traffic in-AZ where possible (balance with HA), use CloudFront for egress, VPC endpoints, and S3 same-region access.

### Q75. Performance efficiency
Choose instance families by workload, use Nitro/ENA, placement groups for HPC, EBS tuning, caching layers, async processing, read replicas, CDN, connection pooling (RDS Proxy), compression, HTTP/2, database indexing, and benchmark with realistic load.

### Q76. Monitoring & alerting strategy
SLO-based alarms (error rate/latency), composite alarms, anomaly detection, log metric filters, synthetics, dashboards per service, alarm actions to SNS/PagerDuty/Chatbot, runbooks linked, EventBridge for automated remediation (SSM Automation/Lambda).

### Q77. Compliance & governance automation
Config conformance packs, Security Hub standards (CIS, PCI), Control Tower guardrails, Audit Manager, tag policies, SCP deny rules (regions, services), CloudTrail organization trail, automated remediation, evidence reports for SOC 2/ISO/HIPAA (BAA).

### Q78. Migration strategies (7 Rs)
Rehost (lift-and-shift), Replatform, Refactor, Repurchase, Retire, Retain, Relocate. Tools: Application Migration Service (MGN), Database Migration Service + SCT, DataSync, Snow family, Migration Hub. Phases: assess, mobilize, migrate/modernize; landing zone first.

### Q79. Blue/green and canary on AWS
CodeDeploy for EC2/ECS/Lambda traffic shifting (linear/canary configurations with alarms and rollback), Route 53 weighted records, ALB weighted target groups, Lambda aliases with weights, API Gateway canary stages, App Mesh/Istio for mesh-level control.

### Q80. Troubleshooting connectivity
Check security groups (both ends), NACLs, route tables, IGW/NAT, DNS resolution, VPC endpoints policies, Flow Logs (REJECT entries), Reachability Analyzer, instance OS firewall/listening ports, target health checks on load balancers.

### Q81. Troubleshooting Lambda

# 🐞 Part 7: Debugging Scenarios

### D1. `AccessDenied` calling S3/KMS/SQS
Check identity policy, resource policy, SCPs, permission boundary, KMS key policy and grants, VPC endpoint policy, Block Public Access, and cross-account trust. Read CloudTrail's `errorMessage` and use the Policy Simulator.

### D2. EC2 can't reach the internet
Route to NAT/IGW missing, NAT in wrong subnet, security group egress, NACL denies, instance in public subnet without public IP/EIP, DNS issues. Use Reachability Analyzer and Flow Logs.

### D3. 502/504 from ALB
Targets unhealthy, app crash, health check path/port wrong, idle timeout shorter than backend processing, security group between ALB and targets, slow backend. Check target health reasons and access logs.

### D4. Lambda timeouts or throttling
Downstream latency, cold starts in VPC, under-provisioned memory, concurrency limit (429), long synchronous chains, retries amplifying load. Add timeouts/backoff, raise memory, reserved/provisioned concurrency, queue buffering.

### D5. DynamoDB throttling (`ProvisionedThroughputExceeded`)
Hot partition or insufficient capacity; use on-demand/auto scaling, better key distribution, batching with backoff, caching with DAX, avoid scans.

### D6. RDS high CPU / connections exhausted
Missing indexes, N+1 queries, connection storms from Lambda/autoscaling; add RDS Proxy, tune queries via Performance Insights, scale up/read replicas, set max connection per service.

### D7. S3 403 on presigned URL
Expired URL, role session expiry shorter than URL, signature mismatch (region/host/headers), bucket policy conditions, KMS permissions for the signer, clock skew.

### D8. Unexpected AWS bill
Cost Explorer by service/usage type, NAT data processing, cross-AZ/inter-region transfer, forgotten resources (EBS, EIPs, snapshots, idle LBs), CloudWatch Logs ingestion, S3 requests/Glacier retrievals, runaway Lambda. Add budgets and anomaly alerts; tag everything.

### D9. Auto Scaling not scaling out/in
Wrong metric/target, cooldowns, max limit reached, health check grace, insufficient capacity in AZ/instance type (use mixed types), quotas hit, scale-in protection. Check activity history.

### D10. ECS tasks keep stopping
Essential container exit code, health check fails, OOM (memory limit), image pull errors (ECR permissions/NAT), missing secrets/permissions, port mismatch. Read stopped task reason and logs.

### D11. CloudFront serves stale/old content
Cache TTL/behaviors, missing invalidation, query string/header cache keys, origin cache-control headers, versioned asset naming absent. Invalidate or version assets.

### D12. Cross-account access fails
Missing trust policy principal, no `sts:AssumeRole` permission on the caller, resource policy blocks, external ID mismatch, SCP deny. Verify both sides.

### D13. Terraform/CloudFormation drift or stuck stack
Manual changes, deletion protection, dependencies/cyclic references, `DELETE_FAILED` due to non-empty buckets/ENIs; use drift detection, retain policies, and clean dependencies manually before retry.

### D14. Route 53 / DNS not resolving
Wrong hosted zone (public vs private), NS delegation mismatch, TTL caching, alias target typos, health-check failover policies, VPC DNS settings.

### D15. Kinesis/SQS consumer lag
Under-provisioned shards/consumers, slow processing, poison messages, iterator age growing; scale consumers, enhanced fan-out, DLQ, batch tuning.

# 🧩 Part 8: Tricky Questions

### T1. Is an AZ a single data center?
Not necessarily; it's one or more discrete data centers with redundant power/networking in a region.

### T2. Does Multi-AZ RDS give read scaling?
No (standby isn't readable for classic RDS Multi-AZ); use read replicas. Aurora replicas serve reads and act as failover targets.

### T3. Are security groups stateful?
Yes: return traffic for allowed connections is automatically allowed; NACLs are stateless.

### T4. Is S3 a file system?
No; it's an object store with flat keys (prefixes simulate folders). Use EFS/FSx for POSIX semantics.

### T5. Is encryption with SSE-S3 enough for compliance?
Depends; SSE-KMS gives key-level audit/control and policy separation. Choose per requirement.

### T6. Does NAT Gateway provide inbound access?
No; outbound-initiated flows only.

### T7. Is IAM regional?
IAM is global (not region-specific); STS has regional endpoints; some services are global-ish (Route 53, CloudFront).

### T8. Do Lambda functions always cold start?
No; warm environments are reused but not guaranteed; cold starts depend on traffic patterns, runtime, package size and VPC.

### T9. Is DynamoDB schemaless?
Only for non-key attributes; keys are defined, and access patterns must be designed up front.

### T10. Does Auto Scaling replace bad instances automatically?
Yes, based on health checks (EC2 and optionally ELB); ensure grace periods are tuned.

### T11. Can you encrypt an existing unencrypted RDS instance in place?
No; snapshot → copy with encryption → restore, then cut over.

### T12. Are VPC peering connections transitive?
No; use Transit Gateway for transitive routing.

### T13. Is Spot safe for databases?
Generally no; use for stateless, interruptible workloads with interruption handling.

### T14. Does CloudFront cache POST?
Not by default; only GET/HEAD (and OPTIONS optionally) are cached.

### T15. Is the root account needed daily?
No; use it only for tasks that require it, protect with MFA, and avoid access keys.

### T16. Are IAM users the recommended way for humans?
No; use IAM Identity Center (federation) with short-lived credentials.

### T17. Does tagging reduce costs by itself?
No; it enables allocation and governance, but you must act on the insights.

### T18. Does Lambda scale infinitely?
Bounded by account/region concurrency quotas and downstream limits; scale controls (reserved concurrency) protect dependencies.

# 🔬 Part 12: AWS Internals

### I1. Region and AZ architecture
Each region has ≥3 AZs (most), separated by meaningful distance but connected by redundant low-latency fiber. Regional services (S3, DynamoDB, SQS) span AZs; zonal resources (EC2, EBS, subnets) are in one AZ. AZ names are mapped per account (use AZ IDs like `aps1-az1` for cross-account consistency).

### I2. Nitro system
Offloads virtualization, networking and storage to dedicated hardware/firmware; delivers near bare-metal performance, strong isolation, and features like EBS NVMe, ENA networking, enclaves (Nitro Enclaves).

### I3. IAM evaluation logic
Request context → collect applicable policies (SCPs, boundaries, session, identity, resource) → explicit deny wins → require an allow in each applicable layer (same-account resource policies can allow on their own for principals in the account) → otherwise implicit deny.

### I4. S3 internals (conceptual)
Objects replicated across ≥3 AZs, strong consistency via metadata subsystem; request partitioning by prefix automatically scales; multipart assembles parts atomically; lifecycle and replication are asynchronous background processes.

### I5. DynamoDB internals
Partitions of up to ~10 GB with 3 replicas across AZs (Paxos-based leader per partition); requests routed by partition key hash; adaptive capacity rebalances hot items; GSIs are eventually consistent copies maintained asynchronously.

### I6. Lambda execution model
Firecracker microVMs host execution environments; the service routes invokes to warm environments or initializes new ones (download code, start runtime, run init); concurrency equals simultaneous environments; Provisioned Concurrency pre-initializes them; SnapStart snapshots initialized state.

### I7. VPC data plane
Hyperplane powers NAT Gateway, NLB, PrivateLink and Lambda ENIs; packets are encapsulated and mapped by the VPC network; security groups are enforced at the hypervisor/ENI level; routing uses route tables evaluated by longest prefix match.

### I8. Global infrastructure services
Route 53 (anycast DNS), CloudFront (edge/regional edge caches), Global Accelerator (anycast IPs to AWS backbone), IAM/Organizations (global control planes with regional data planes). Control planes are less available than data planes: design failover on data-plane health.

### I9. Shared responsibility by service tier
EC2: you manage OS, patches, firewall; RDS: AWS manages OS/patching, you manage schema/access; Lambda: AWS manages runtime infra, you manage code/permissions; S3: you manage access policies/encryption choices.

# 🔮 Part 14: Output & Prediction Questions

### O1.
IAM policy allows `s3:*` but an SCP denies `s3:DeleteBucket`; a user calls DeleteBucket.
**Result:** denied (SCP/explicit deny wins).

### O2.
Instance in a private subnet, route table has `0.0.0.0/0 → igw`.
**Result:** the subnet is effectively public; it still needs a public IP for internet reachability.

### O3.
Security group allows inbound 443 only; outbound default allow all.
**Result:** responses to inbound connections work (stateful); other inbound is blocked.

### O4.
Lambda concurrency limit reached on a synchronous API.
**Result:** `429 TooManyRequestsException`/throttling for new requests.

### O5.
S3 object overwritten, then immediately read.
**Result:** returns the new object (strong read-after-write consistency).

### O6.
RDS Multi-AZ primary fails.
**Result:** automatic failover to standby (~1-2 minutes); DNS endpoint stays the same; connections must reconnect.

### O7.
DynamoDB item with partition key `userId=1` receives most traffic.
**Result:** hot partition throttling despite spare table capacity.

### O8.
Two VPCs peered (A–B) and B–C; A calls C.
**Result:** fails (peering is non-transitive).

### O9.
Spot instance receives interruption notice.
**Result:** ~2 minutes to checkpoint/drain before termination.

### O10.
CloudFront cert created in `ap-south-1`.
**Result:** can't be used; CloudFront requires ACM certs in `us-east-1`.

### O11.
Public S3 bucket policy added but Block Public Access enabled.
**Result:** public access remains blocked.

### O12.
ASG min=2, desired=2, max=6, CPU target 50%, load rises to 80%.
**Result:** target tracking adds instances until average CPU ~50% or max reached, after warmup.

# ⚠️ Part 16: Common Mistakes

1. **Using root or long-lived access keys**; no MFA.
2. **Overly broad IAM (`*:*`)** and no Access Analyzer reviews.
3. **Public S3 buckets/security groups open to 0.0.0.0/0** on admin ports.
4. **Single-AZ architectures** and untested failover.
5. **No backups or untested restores.**
6. **Ignoring data transfer and NAT costs.**
7. **Untagged resources** and no budgets/alerts.
8. **Manual console changes** instead of IaC.
9. **Hard-coded secrets**; no rotation.
10. **Unencrypted data** at rest/in transit.
11. **No CloudTrail/Config/GuardDuty** across accounts and regions.
12. **Lambda in VPC without NAT/endpoints** (timeouts) or unlimited concurrency hammering DBs.
13. **DynamoDB scans and hot keys.**
14. **Oversized instances / no autoscaling.**
15. **Using one account for everything.**
16. **Skipping service quota checks** before launches.
17. **Relying on control-plane operations during failover.**
18. **No alarm on `AccessDenied`/billing anomalies.**
19. **Public RDS instances** or default credentials.
20. **Using IAM users for humans** instead of SSO.
21. **No lifecycle rules** for logs/snapshots/S3.
22. **Ignoring IMDSv2** and instance metadata exposure.
