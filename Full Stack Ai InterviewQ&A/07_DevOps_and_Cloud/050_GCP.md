# 🟢 Part 1: Fresher (0–1 year)

### Q1. What is GCP? *(Must-know)*
Google Cloud Platform: Google's public cloud, built on the same infrastructure as Search, YouTube and Gmail. Known for a global private fiber network, strong data/analytics (BigQuery), Kubernetes (GKE, born from Borg), serverless containers (Cloud Run) and AI (Vertex AI, Gemini).

### Q2. Regions, zones and multi-regions *(Must-know)*
A **region** (e.g., `asia-south1` Mumbai) has ≥3 **zones** (`asia-south1-a`). Some services are zonal (VMs, Persistent Disks), regional (regional MIGs, Cloud SQL HA, GKE regional clusters) or global/multi-regional (Cloud Storage multi-region buckets, BigQuery datasets, global load balancer, Spanner configs). Design for zone failure at minimum.

### Q3. Resource hierarchy *(Must-know)*
Organization → Folders → **Projects** → Resources. Projects are the base unit for billing, APIs enablement, IAM and quotas. Policies (IAM, Organization Policy) inherit downward. Use folders per environment/team and separate projects for prod/non-prod and shared services.

### Q4. Cloud IAM fundamentals *(Must-know)*
Who (principal: user, group, service account, workload identity) can do what (role = set of permissions) on which resource (scope: org/folder/project/resource). Role types: basic (Owner/Editor/Viewer: avoid), predefined (e.g., `roles/storage.objectViewer`), custom. Allow policies are additive; **deny policies** and **IAM conditions** refine. Prefer groups and least privilege.

### Q5. Service accounts
Identities for workloads. Attach to VMs/Cloud Run/GKE (Workload Identity) so apps use short-lived tokens via the metadata server; avoid downloading JSON keys. Grant minimal roles; use impersonation (`roles/iam.serviceAccountTokenCreator`) instead of keys; separate SAs per workload.
```bash
gcloud iam service-accounts create api-sa --display-name "API"
gcloud projects add-iam-policy-binding my-proj --member "serviceAccount:api-sa@my-proj.iam.gserviceaccount.com" --role roles/cloudsql.client
```

### Q6. Workload Identity Federation
Lets external identities (GitHub Actions OIDC, AWS, Azure) access GCP without service account keys, mapping provider claims to service accounts. Replaces long-lived keys in CI. On GKE, **Workload Identity** maps Kubernetes ServiceAccounts to IAM.

### Q7. Compute Engine basics
VMs with machine families (E2 cost-optimized, N2/N4 general, C3 compute, M memory, A3/G2 GPU, T2A Arm), custom machine types, images, startup scripts, metadata, preemptible/**Spot VMs**, sole-tenant nodes, OS Login with IAM, per-second billing, sustained/committed-use discounts.

### Q8. Managed Instance Groups (MIGs)
Identical VMs from an instance template; autoscaling, autohealing (health checks), rolling updates, regional MIGs spread across zones. Stateless MIGs behind a load balancer are the standard scalable VM pattern.

### Q9. VPC in GCP *(Must-know)*
**Global** VPC networks with regional subnets (no per-zone subnets); routes and firewall rules are network-wide; auto vs custom mode subnets (use custom). Firewall rules are stateful, applied by network tags/service accounts, with implied deny ingress/allow egress; hierarchical firewall policies at org/folder.

### Q10. Cloud NAT, Private Google Access and Private Service Connect
Cloud NAT gives outbound internet to private VMs; Private Google Access lets VMs without external IPs reach Google APIs; **Private Service Connect** exposes managed/published services via private endpoints; VPC peering and Shared VPC connect networks.

### Q11. Shared VPC vs VPC peering
Shared VPC: host project owns the network; service projects use its subnets (central network governance). VPC peering: connect separate VPCs privately (non-transitive; no overlapping ranges). Network Connectivity Center for hub-and-spoke at scale.

### Q12. Cloud Load Balancing *(Must-know)*
Global external Application LB (L7, single anycast IP, URL maps, Cloud CDN/Armor), regional external/internal Application LB, external/internal Network LB (L4 passthrough), proxy Network LB. Global LB routes to the closest healthy backend across regions.

### Q13. Cloud Storage (GCS)
Object storage with buckets; classes: Standard, Nearline (30d), Coldline (90d), Archive (365d); location types: regional, dual-region, multi-region; features: versioning, lifecycle, retention/holds, signed URLs, uniform bucket-level access (IAM only), CMEK, Autoclass, event notifications to Pub/Sub. Strong global consistency.

### Q14. Persistent Disk and Filestore
Zonal/regional Persistent Disk (pd-balanced, pd-ssd, Hyperdisk), snapshots, local SSD (ephemeral); Filestore managed NFS. Choose by IOPS/throughput and durability needs.

### Q15. Cloud SQL, AlloyDB, Spanner
Cloud SQL: managed MySQL/PostgreSQL/SQL Server with HA (regional), read replicas, backups/PITR. AlloyDB: PostgreSQL-compatible high-performance. **Spanner**: globally distributed relational with strong consistency and horizontal scale (TrueTime). See `../04_Database/`.

### Q16. NoSQL: Firestore and Bigtable
Firestore: serverless document DB with real-time sync and strong consistency (see `../03_Backend/034_Firebase-and-Supabase.md`). Bigtable: wide-column, very high throughput/low latency for time-series/IoT (HBase API), row-key design critical.

### Q17. BigQuery *(Must-know)*
Serverless data warehouse: separation of storage and compute, columnar storage (Capacitor), SQL (GoogleSQL), on-demand (per TB scanned) or capacity pricing (slots/editions), partitioned and clustered tables, streaming and batch ingestion, BigQuery ML, materialized views, authorized views, BI Engine.
```sql
SELECT user_id, COUNT(*) AS orders
FROM `proj.sales.orders`
WHERE order_date BETWEEN '2025-10-01' AND '2025-10-24'   -- partition pruning
GROUP BY user_id ORDER BY orders DESC LIMIT 10;
```

### Q18. Pub/Sub
Global messaging: topics, subscriptions (pull/push/BigQuery/Cloud Storage), at-least-once delivery, ordering keys, dead-letter topics, message retention/replay (seek), exactly-once for pull subscriptions in region, filters. See `../03_Backend/038_Message-Queues.md`.

### Q19. Cloud Run *(Must-know)*
Serverless containers: deploy any stateless container, HTTP/gRPC, scale to zero, concurrency per instance (default 80), request timeout up to 60 min, revisions with traffic splitting, VPC connector/Direct VPC egress, IAM-based invocation, min instances to avoid cold starts. Cloud Run jobs for batch.
```bash
gcloud run deploy api --image asia-south1-docker.pkg.dev/proj/repo/api:1.0 --region asia-south1 --service-account api-sa --no-allow-unauthenticated --min-instances 1
```

### Q20. Cloud Functions & App Engine
Cloud Functions (2nd gen, built on Cloud Run/Eventarc): event-driven snippets. App Engine: older PaaS (Standard/Flexible). Prefer Cloud Run for new services.

### Q21. GKE: Autopilot vs Standard
Autopilot: Google manages nodes (pay per Pod resources), opinionated security defaults; Standard: you manage node pools. Features: regional clusters, release channels, Workload Identity, Gateway API, Anthos/Fleet management, node auto-provisioning. See `046_Kubernetes.md`.

### Q22. Artifact Registry
Stores container images and language packages (npm, Maven, Python), regional/multi-regional repos, IAM, vulnerability scanning, remote/virtual repositories. Replaces Container Registry.

### Q23. Cloud Build and Cloud Deploy
Cloud Build: serverless CI (YAML steps, triggers from GitHub/GitLab, private pools). Cloud Deploy: managed delivery pipelines to GKE/Cloud Run with promotion, approvals, canary. GitHub Actions + WIF is also common. See `047_CI-CD-and-DevOps.md`.

### Q24. Secret Manager and KMS
Secret Manager stores versioned secrets with IAM and rotation notifications; Cloud KMS manages keys (software/HSM/EKM), CMEK integrates with many services, automatic rotation, key rings/regions. Access via service accounts at runtime.

### Q25. Cloud Monitoring & Logging
Metrics (Monarch-backed), dashboards, alerting policies (SLO-based), uptime checks, Managed Service for Prometheus, Logging (Log Explorer, log-based metrics, sinks to BigQuery/Storage/Pub/Sub), Trace, Profiler, Error Reporting. Audit logs: Admin Activity (always on), Data Access (opt-in). See `052_Monitoring-and-Observability.md`.

### Q26. Infrastructure as Code
Terraform (google provider) is the standard; Config Connector for Kubernetes-style management; Deployment Manager is legacy; Infrastructure Manager (managed Terraform). See `051_Terraform-and-IaC.md`.

### Q27. gcloud CLI essentials
```bash
gcloud auth login && gcloud config set project my-proj
gcloud compute instances list
gcloud storage cp report.pdf gs://my-bucket/reports/
gcloud logging read 'severity>=ERROR' --limit 20
gcloud projects get-iam-policy my-proj --format=json
```

### Q28. Pricing basics
Per-second billing, sustained use discounts (automatic on some families), committed use discounts (CUDs: resource- or spend-based), Spot VMs (up to ~60-91% off), free tier, egress charges (inter-region/internet), BigQuery query vs capacity pricing. Use Budgets/alerts and the Pricing Calculator.

### Q29. Architecture Framework pillars
Operational excellence, security/privacy/compliance, reliability, cost optimization, performance optimization (plus sustainability/AI lenses). Use the framework and Active Assist/Recommender for improvements.

### Q30. Organization Policy
Constraints enforced across the hierarchy: restrict resource locations, disable service account key creation, require OS Login, restrict public IPs, domain-restricted sharing, uniform bucket-level access. Powerful guardrails distinct from IAM.

# 🔵 Part 2: Junior (1–3 years)

### Q31. IAM deep dive *(Must-know)*
Policy bindings (member + role + optional condition) at any hierarchy level; effective permissions = union of inherited allows minus deny policies. Conditions use CEL (time, resource name, tags). Use **IAM Recommender** to remove excess permissions, **Policy Troubleshooter** to debug, **principal access boundaries** to limit scope (verify availability).
```bash
gcloud projects add-iam-policy-binding proj --member group:devs@example.com --role roles/run.developer \
  --condition='expression=request.time < timestamp("2026-01-01T00:00:00Z"),title=temp-access'
```

### Q32. Avoiding service account keys
Use attached SAs, Workload Identity (GKE), WIF for CI, impersonation for humans/tools, short-lived tokens (`gcloud auth print-access-token --impersonate-service-account`). Enforce `iam.disableServiceAccountKeyCreation`. Rotate/inventory any unavoidable keys.

### Q33. VPC design *(Must-know)*
Custom-mode VPC, regional subnets with sized primary and secondary ranges (GKE Pods/Services), private IPs by default, Cloud NAT per region, Private Google Access, firewall rules via tags/service accounts (prefer service-account-based), hierarchical policies for baseline, Shared VPC for multi-project, Cloud Router/BGP for hybrid.

### Q34. Hybrid connectivity
Cloud VPN (HA VPN 99.99%), Cloud Interconnect (Dedicated/Partner), Cloud Router dynamic routing, Network Connectivity Center, Private Service Connect for service exposure, Cloud DNS forwarding/peering. Plan CIDRs to avoid overlap.

### Q35. Load balancer selection
| Need | Choose |
|---|---|
| Global HTTP(S) with CDN/Armor | Global external Application LB |
| Internal microservices HTTP | Internal Application LB |
| TCP/UDP passthrough, preserve client IP | Network LB (passthrough) |
| gRPC/HTTP2 | Application LB / Cloud Run |
Health checks and backend services (NEGs for serverless/GKE) are core objects.

### Q36. Cloud CDN & Cloud Armor
CDN caches at Google edge (cache modes, signed URLs); Cloud Armor provides WAF rules, DDoS protection, rate limiting, geo/IP policies, bot management, preconfigured OWASP rules (attached to backend services).

### Q37. Compute Engine operations
Instance templates, MIGs with autoscaling on CPU/LB utilization/custom metrics, autohealing, rolling/canary updates, OS patch management (VM Manager), Shielded VM, Confidential VMs, snapshots/images, OS Login + IAP TCP forwarding (no public SSH).
```bash
gcloud compute ssh vm-1 --tunnel-through-iap --zone asia-south1-a
```

### Q38. Spot VMs
Up to ~91% cheaper, preemptible at any time (30 s notice), no max runtime; use for fault-tolerant batch, CI runners, stateless workers with MIGs and graceful shutdown scripts.

### Q39. Cloud Run in depth *(Must-know)*
Concurrency tuning, CPU allocation (request-only vs always-allocated), startup CPU boost, min/max instances, revisions + traffic splits (canary), secrets as env/volume mounts, VPC egress (Direct VPC), ingress controls (internal/LB), custom domains/IAP, authentication (Cloud Run invoker IAM, OIDC tokens), sidecars, GPU support (verify), jobs and worker pools.

### Q40. Choosing Cloud Run vs GKE vs Functions vs App Engine
| Need | Choice |
|---|---|
| Stateless HTTP containers, minimal ops | Cloud Run |
| Kubernetes APIs/operators, complex workloads | GKE |
| Event glue code | Cloud Functions (2nd gen) |
| Legacy PaaS apps | App Engine |
| Full OS control | Compute Engine |

### Q41. GKE operations
Release channels (Rapid/Regular/Stable), auto-upgrade and maintenance windows, node auto-repair, node auto-provisioning, Workload Identity, private clusters (control plane private endpoint), Gateway API/Ingress, Binary Authorization, GKE Sandbox (gVisor), network policy (Dataplane V2/Cilium), Cost allocation. See `046_Kubernetes.md`.

### Q42. Cloud Storage security
Uniform bucket-level access, no public access prevention (enforce org-wide), signed URLs/policy documents, CMEK, VPC Service Controls, retention policies/Bucket Lock, object versioning, audit logs, IAM Conditions on prefixes (resource name), Private Google Access.

### Q43. Cloud SQL operations
Regional HA (synchronous replica in another zone, automatic failover), read replicas (cross-region), automated backups + PITR, maintenance windows, private IP via Private Service Access, Cloud SQL Auth Proxy/connectors (IAM auth), connection limits and pooling (PgBouncer), flags tuning, Query Insights.

### Q44. Spanner design
Choose primary keys to avoid hotspots (no monotonically increasing keys; use hashed/UUID or bit-reversed sequences), interleaved tables/parent-child, secondary indexes, regional vs multi-region configs, processing units for sizing, read-only/stale reads for latency, strong external consistency. Use when you need global scale + relational semantics.

### Q45. Bigtable design
Row-key design drives performance: avoid hot-spotting (don't use timestamps as prefixes), field promotion, reverse timestamps, salting; column families with GC policies; cluster replication for HA; use for time-series, IoT, ad-tech.

### Q46. Firestore modes
Native mode (real-time listeners, mobile/web SDKs) and Datastore mode (server-focused). Indexes automatic/composite, document size 1 MiB, strong consistency, multi-region replication. Pricing by operations.

### Q47. BigQuery optimization *(Must-know)*
Partition by date/ingestion time and cluster by common filters; select only needed columns (avoid `SELECT *`); use approximate aggregates where fine; materialized views; avoid cross joins; use slots/editions reservations for predictable cost; `INFORMATION_SCHEMA.JOBS` to find expensive queries; table expiration; load vs streaming trade-offs; denormalize with nested/repeated fields.

### Q48. BigQuery security & governance
Dataset/table IAM, column-level security (policy tags), row-level security, authorized views/datasets, CMEK, VPC Service Controls, audit logs, Data Catalog/Dataplex for governance, DLP API for PII discovery.

### Q49. Dataflow and Dataproc
Dataflow: managed Apache Beam (batch + streaming, autoscaling, exactly-once with Pub/Sub, windowing/watermarks). Dataproc: managed Spark/Hadoop clusters (ephemeral, serverless Spark option). Composer: managed Airflow for orchestration. See `../10_AI_and_ML/075_Data-Engineering.md`.

### Q50. Pub/Sub patterns
Fan-out via multiple subscriptions, push to Cloud Run, BigQuery subscriptions (direct ingest), ordering keys (per-key order), dead-letter topics with max delivery attempts, exactly-once delivery (pull), snapshot/seek for replay, ack deadlines and flow control, idempotent consumers.

### Q51. Eventarc and Workflows
Eventarc routes events (Cloud Audit Logs, Pub/Sub, direct sources) to Cloud Run/Functions/Workflows; **Workflows** orchestrates serverless steps with retries, conditions and callbacks; Cloud Scheduler triggers cron jobs; Cloud Tasks for rate-limited task queues.

### Q52. API Gateway, Apigee, Endpoints
API Gateway: simple managed gateway for serverless backends; Apigee: full API management (policies, monetization, analytics); Cloud Endpoints (ESP) legacy. Use IAP/Identity Platform for user auth.

### Q53. Identity-Aware Proxy (IAP) & BeyondCorp
IAP enforces context-aware access to web apps and SSH/RDP without VPN using Google identities; combine with Access Context Manager levels (device, location). Supports Cloud Run, GKE, App Engine, Compute backends.

### Q54. VPC Service Controls *(Must-know)*
Service perimeters around projects/APIs to mitigate data exfiltration (e.g., prevent copying BigQuery/GCS data to outside projects even with valid credentials). Configure ingress/egress rules, access levels, dry-run mode first. Complements IAM.

### Q55. Security Command Center
Central posture and threat findings (Premium: misconfigurations, vulnerabilities, threat detection like Event Threat Detection, Container Threat Detection), compliance dashboards, integrations with SIEM, attack path simulation.

### Q56. Logging architecture
Aggregated sinks at org/folder level to central project/BigQuery/Storage, log buckets with retention, exclusion filters to control cost, log-based metrics/alerts, audit log configuration (Data Access logs where needed), Log Analytics (BigQuery-backed queries).

### Q57. Observability with SLOs
Service Monitoring defines SLIs/SLOs on request-based or windows-based metrics, error budget burn alerts, uptime checks, Cloud Trace via OpenTelemetry, Managed Prometheus for Kubernetes, Profiler for CPU/heap hot spots.

### Q58. Terraform on GCP
Remote state in GCS with locking, WIF-authenticated pipelines, project factory modules, org policy as code, Cloud Foundation Toolkit modules, drift checks, separate state per environment/project. See `051_Terraform-and-IaC.md`.

### Q59. Backup & DR
Cloud SQL backups/replicas, Spanner backups/multi-region, GCS dual/multi-region and Object Versioning, snapshot schedules for disks, Backup and DR Service, BigQuery time travel (7 days) and table snapshots, multi-region load balancing, runbooks and tested failover.

### Q60. Cost management
Billing export to BigQuery, budgets/alerts, labels for allocation, Recommender (rightsizing, idle resources), CUDs, Spot, autoscaling, BigQuery slot reservations/editions, storage lifecycle/Autoclass, egress reduction (CDN, same-region traffic), Cloud Run scale to zero.

# 🟡 Part 3: Mid (3–5 years)

### Q61. Designing highly available apps on GCP *(Must-know)*
Regional MIGs/GKE regional clusters across ≥3 zones, global load balancer with health checks, Cloud Run (regional, multi-zone by default), Cloud SQL HA + read replicas, Spanner/multi-region storage where needed, stateless services, graceful shutdown, circuit breakers/retries, and chaos testing. Remember SLAs are per-service; composite availability is the product.

### Q62. Multi-region architecture
Global external LB with backends in several regions (automatic failover/proximity), data tier choice: Spanner multi-region, Firestore multi-region, GCS dual/multi-region, Cloud SQL cross-region replicas (promote on failover), BigQuery multi-region datasets. Define RPO/RTO, replicate secrets/config, DNS/TTL, runbooks and drills.

### Q63. Landing zone and resource organization
Org policies, folders (prod/non-prod/shared/sandbox), projects per workload/environment, central logging and security projects, Shared VPC host projects, billing structure, naming and labeling standards, IaC project factory, groups-based IAM, break-glass accounts, and Cloud Foundation Toolkit blueprints.

### Q64. Shared VPC design
Host project defines subnets and firewall; service projects attach and deploy resources into allowed subnets (IAM `compute.networkUser`). Central network team controls routing/security, app teams own workloads. Combine with hierarchical firewall policies and Private Service Connect for service publishing.

### Q65. Private access patterns
No external IPs, Cloud NAT for egress, Private Google Access for APIs, Private Service Connect endpoints for Google APIs/published services, Private Service Access for managed services (Cloud SQL), DNS zones (`googleapis.com` private/restricted VIPs) and VPC-SC for exfiltration control.

### Q66. Zero Trust on GCP
BeyondCorp: IAP + Access Context Manager (device/identity/location), IAM least privilege with conditions, Workload Identity (no keys), VPC-SC perimeters, Binary Authorization, Security Command Center, continuous monitoring and audit logs.

### Q67. Encryption and key management
Default Google-managed encryption; CMEK via Cloud KMS for storage/BigQuery/SQL/Disks; Cloud HSM/EKM for stricter control; envelope encryption; key rotation; separate key projects; monitor key usage (audit logs); Confidential VMs/GKE nodes for data in use.

### Q68. Secrets handling
Secret Manager with IAM per secret, versions and rotation (Pub/Sub notifications + function), regional secrets, mount in Cloud Run/GKE (CSI), avoid env var dumps for highly sensitive data, audit access, replication policies (automatic vs user-managed).

### Q69. Data platform architecture
Ingest (Pub/Sub, Datastream CDC, Storage Transfer, Dataflow) → lake (GCS, open formats) → warehouse (BigQuery, BigLake) → transform (dbt, Dataform, Dataflow) → serve/BI (Looker) → ML (Vertex AI). Governance with Dataplex/Data Catalog, lineage, DLP. Cost control via partitioning, reservations, and storage tiers.

### Q70. Streaming architecture
Producers → Pub/Sub → Dataflow (windowing, dedupe, late data) → BigQuery/Bigtable → dashboards/alerts. Use dead-letter topics, idempotent sinks, backpressure handling, replay via Pub/Sub seek or raw GCS archive, and monitoring of subscription backlog/oldest unacked age.

### Q71. Vertex AI and generative AI
Vertex AI: managed ML platform (Workbench, training, pipelines, Feature Store, Model Registry, endpoints), Model Garden/Gemini APIs, grounding with Vertex AI Search, vector search, evaluation, safety filters, VPC-SC and CMEK support, quotas. RAG patterns with BigQuery/AlloyDB (pgvector) or Vertex vector search. See `../11_Generative_AI/` and `../10_AI_and_ML/074_MLOps.md`.

### Q72. CI/CD to GCP with WIF
```yaml
permissions: { id-token: write, contents: read }
steps:
  - uses: google-github-actions/auth@v2
    with: { workload_identity_provider: projects/123/locations/global/workloadIdentityPools/gh/providers/github, service_account: deploy@proj.iam.gserviceaccount.com }
  - uses: google-github-actions/deploy-cloudrun@v2
    with: { service: api, region: asia-south1, image: asia-south1-docker.pkg.dev/proj/repo/api:${{ github.sha }} }
```
Restrict the provider with attribute conditions (repo/branch).

### Q73. Cloud Deploy pipelines
Delivery pipeline with targets (dev → staging → prod), Skaffold-based rendering, approvals, canary/blue-green strategies for GKE/Cloud Run, automated verification jobs, rollback, audit. Integrates with Cloud Build and Artifact Registry.

### Q74. Binary Authorization & supply chain
Attestors sign images after CI checks (vulnerability scan, provenance); policies on GKE/Cloud Run require attestations; Artifact Analysis scans; SLSA provenance from Cloud Build; break-glass override with audit. See `045_Docker.md`.

### Q75. Autoscaling strategies
MIG autoscaler (CPU, LB capacity, Pub/Sub backlog via custom metrics), GKE HPA/VPA/Node auto-provisioning/Autopilot, Cloud Run concurrency-based scaling, Dataflow autoscaling, BigQuery slot autoscaling (editions), Spanner autoscaler. Tune cooldowns and max limits; load test.

### Q76. Performance optimization
Co-locate compute and data in the same region, use Premium Tier networking and global LB, CDN, Memorystore caching, connection pooling (Cloud SQL), BigQuery partitioning/clustering, Spanner schema design, GKE node pool right-sizing, gRPC/HTTP2, profiling with Cloud Profiler/Trace.

### Q77. Troubleshooting networking
Connectivity Tests (reachability analysis), VPC Flow Logs, firewall rules logging, Packet Mirroring, routes inspection, Cloud NAT logs and port exhaustion, DNS (Cloud DNS logs, private zones), LB health checks and backend logs, Private Service Connect status.

### Q78. Troubleshooting Cloud Run
Logs in Cloud Logging, revision status/errors, container must listen on `$PORT` and start within timeout, memory/CPU limits (OOM), cold starts (min instances), VPC egress config, IAM invoker permissions (403), concurrency issues with shared state, request timeouts.

### Q79. Troubleshooting GKE
`kubectl describe`, GKE logs/metrics, node pool health (auto-repair), IP exhaustion (secondary ranges), quota limits, Workload Identity misconfig (403 on APIs), image pull from Artifact Registry permissions, Gateway/Ingress backend health, upgrade-induced disruption (PDBs).

### Q80. Troubleshooting IAM
Policy Troubleshooter for principal/permission/resource, check inherited deny policies and Org Policy constraints, service account impersonation permissions, API not enabled in the project, VPC-SC perimeter blocks (error mentions "Request is prohibited by organization's policy"), audit logs for `PERMISSION_DENIED` details.

### Q81. Quotas and limits
Per-project and per-region quotas (CPUs, IPs, API rate limits); request increases ahead of launches; monitor quota usage metrics and alert; design retry with exponential backoff for `429/RESOURCE_EXHAUSTED`; split workloads across projects when needed.

### Q82. Migration to GCP
Assess (Migration Center), landing zone, migrate VMs (Migrate to Virtual Machines), databases (Database Migration Service, Datastream), data (Storage Transfer, BigQuery Data Transfer), containers (Migrate to Containers), then modernize. Hybrid options: Anthos/GKE Enterprise, Interconnect.

### Q83. Compliance & residency
Choose regions per residency, Assured Workloads for regulated environments (FedRAMP, CJIS, etc.), Org Policy for location restrictions, Access Transparency/Approval, CMEK/EKM, audit logs retention, DLP, compliance reports.

### Q84. Sustainability
Region carbon-free energy percentages (CFE%), Active Assist for idle resources, serverless and autoscaling, right-sizing; carbon footprint reports for measurement.

# 🟠 Part 4: Senior (5–7 years)

### Q85. Design a scalable, secure web platform on GCP *(Must-know)*

# 🐞 Part 7: Debugging Scenarios

### D1. `PERMISSION_DENIED` calling an API
Missing role at the right scope, API not enabled, deny policy/Org Policy, service account not attached, VPC-SC perimeter. Use Policy Troubleshooter and audit logs.

### D2. Cloud Run 403 when invoking
Caller lacks `roles/run.invoker`, wrong ID token audience, ingress set to internal-only, org policy blocks `allUsers`. Test with `curl -H "Authorization: Bearer $(gcloud auth print-identity-token)"`.

### D3. Cloud Run fails to start ("container failed to listen on PORT")
App listens on wrong port/localhost only, slow startup beyond timeout, crash on missing env/secret. Bind `0.0.0.0:$PORT`, enable startup CPU boost, check logs.

### D4. VM can't reach internet or Google APIs
No external IP and no Cloud NAT, missing Private Google Access, firewall egress denies, DNS config. Add NAT/PGA; run Connectivity Tests.

### D5. GKE pods stuck Pending due to IP exhaustion
Pod secondary range too small or max pods per node; add secondary ranges/new node pool or use larger CIDR in a new cluster (some settings immutable).

### D6. Cloud SQL connection errors
Max connections reached, private IP/PSA misconfig, Auth Proxy credentials, SSL requirements, pooler absent. Use connection pooling and check `max_connections`.

### D7. BigQuery cost spike
Unpartitioned scans, `SELECT *`, repeated dashboard queries. Add partition filters, clustering, BI Engine/materialized views, `maximum_bytes_billed`, reservations; inspect `INFORMATION_SCHEMA.JOBS_BY_PROJECT`.

### D8. Pub/Sub backlog growing
Slow subscribers, ack deadlines too short (redelivery), poison messages without DLQ, insufficient subscriber instances/flow control. Scale consumers, extend ack deadline, add DLQ and monitor oldest unacked age.

### D9. Load balancer 502 or unhealthy backends
Health check path/port mismatch, firewall rules blocking Google health-check ranges (130.211.0.0/22, 35.191.0.0/16), backend timeout, app crash. Allow ranges and align checks.

### D10. Quota exceeded (`RESOURCE_EXHAUSTED`)
Region CPU/IP quotas or API rate limits. Check quota page, request increases, add backoff, spread across regions/projects.

### D11. Terraform apply fails on API enablement/ordering
APIs not enabled yet, eventual consistency in IAM propagation, missing `depends_on`. Enable APIs first (`google_project_service`), add retries/sleep or explicit dependencies.

### D12. Spanner hotspot
Monotonic primary keys or sequential timestamps. Use UUIDv4/hash prefix/bit-reversed sequences; examine key visualizer.

### D13. Service account key leak
Revoke/delete key, check audit logs for use, rotate dependent systems, enforce org policy to disable key creation, move to WIF/attached SAs.

### D14. VPC-SC blocks legitimate access
Request lacks access level or is outside perimeter ingress rules. Use dry-run logs to identify violations, add ingress/egress rules for specific identities/services.

### D15. Logs cost surge
Debug logging in prod, high-volume load balancer/data access logs. Add exclusion filters, route to cheaper storage, adjust levels, sample.

# 🧩 Part 8: Tricky Questions

### T1. Are VPC networks regional in GCP?
No: VPC networks are global; subnets are regional.

### T2. Does a zonal disk survive zone loss?
No; use regional Persistent Disk, snapshots, or replicate at the application layer.

### T3. Is a project a security boundary?
Yes, a strong administrative and IAM boundary (billing, quotas, APIs), though network and policy design still matter.

### T4. Basic roles (Owner/Editor/Viewer) good for production?
No; too broad. Use predefined/custom roles.

### T5. Does Cloud Run always scale to zero?
By default yes with `min-instances=0`; setting min instances keeps warm instances (cost).

### T6. Does BigQuery charge for storage-less queries?
On-demand charges per bytes processed even if results are small; dry-run first and use partition filters.

### T7. Is Pub/Sub ordered?
Not by default; per-ordering-key ordering requires enabling message ordering, and consumer concurrency still matters.

### T8. Can you use the same service account everywhere?
You can, but it violates least privilege; one SA per workload improves blast radius.

### T9. Are Google-managed encryption keys insecure?
No, data is encrypted at rest by default; CMEK adds control, separation of duties and revocation.

### T10. Does Shared VPC mean one project?
No; it connects a host project's network with multiple service projects.

### T11. Does VPC peering give transitive routing?
No; it is non-transitive.

### T12. Is Cloud Functions the best choice for new services?
Often Cloud Run is preferred for flexibility; Functions suits small event handlers.

### T13. Is Spanner just a NoSQL store?
No; it's relational with SQL, strong consistency and horizontal scale.

### T14. Do preemptible/Spot VMs have SLA?
No; they can be reclaimed anytime.

### T15. Does deleting a project delete resources immediately?
It schedules deletion (30-day recovery window) and shuts down resources.

### T16. Is Cloud NAT a firewall?
No; it provides outbound NAT only; use firewall rules/policies for filtering.

### T17. Is Autopilot GKE less flexible than Standard?
Yes, some privileges/node customizations are restricted in exchange for managed operations and per-Pod billing.

### T18. Do IAM conditions replace Org Policy?
No; IAM conditions refine who can do what; Org Policy constrains resource configurations organization-wide.

# 🔬 Part 12: GCP Internals

### I1. Google's global network
Private backbone connecting regions and edge POPs; Premium Tier routes traffic over Google's network from the nearest edge ("cold potato"), Standard Tier uses public internet for most of the path. Global LBs use anycast IPs and Google Front Ends (GFEs).

### I2. Borg, Kubernetes and Cloud Run
Borg (cluster manager) inspired Kubernetes; Cloud Run is based on Knative-style serving atop Google's infrastructure with gVisor-based sandboxes (gen1) or microVM-like gen2 execution environments; autoscaling by concurrency and request load.

### I3. Spanner and TrueTime
TrueTime (GPS + atomic clocks) bounds clock uncertainty, enabling external consistency via commit-wait; data split into splits replicated with Paxos; schema and key design determine hotspotting; multi-region configs trade latency for durability.

### I4. BigQuery architecture
Dremel execution engine (tree of slots), Colossus storage (columnar Capacitor), Jupiter network, Borg scheduling; shuffle service separates compute/storage; query plans in stages; slots are units of compute.

### I5. Pub/Sub architecture
Global service with regional storage replication; messages stored durably until acked; subscriptions maintain per-subscriber state; push/pull flow control; ordering keys route to same partitions; exactly-once uses per-message state tracking in region.

### I6. IAM evaluation
Request → authenticate → gather allow bindings (inherited) → apply deny policies and conditions → Org Policy constraints evaluated separately for resource configuration → VPC-SC checked for API perimeter violations → result logged in audit logs.

### I7. GCS consistency
Strong global consistency for object operations and listings; metadata and data replicated across zones (regional) or regions (dual/multi); composite objects, resumable uploads and parallel composite uploads for large files.

### I8. VPC data plane (Andromeda)
Software-defined network virtualization stack implements VPC routing, firewalling and load balancing on hosts; firewall rules apply at the VM NIC; no central chokepoints, enabling scale.

### I9. GKE control plane
Google-managed Kubernetes masters (regional replicas), automatic upgrades by release channel, nodes on Compute Engine (Standard) or fully managed (Autopilot) with security hardening (Shielded nodes, COS images).

Service account has `roles/editor` on project; org policy `iam.disableServiceAccountKeyCreation` enforced; `gcloud iam service-accounts keys create`.
**Result:** denied by Org Policy regardless of IAM role.

### O3.
Cloud Run `min-instances=0`, idle 15 minutes, then request.
**Result:** cold start latency while a new instance starts.

### O4.
BigQuery partitioned table with `require_partition_filter=TRUE`, query without a partition filter.
**Result:** query error.

### O5.
Pub/Sub subscriber doesn't ack within ack deadline.
**Result:** message redelivered (at-least-once), possibly duplicate processing.

### O6.
Firewall rules default for a new custom VPC.
**Result:** ingress denied (implied), egress allowed; SSH/HTTP need explicit rules.

### O7.
VPC peering A–B and B–C; A to C traffic.
**Result:** not routable (non-transitive).

### O8.
Spanner table with timestamp primary key inserted sequentially at high rate.
**Result:** hotspotting on one split; use hashed or UUID keys.

### O9.
Spot VM receives preemption.
**Result:** 30 s ACPI shutdown notice then termination; MIG recreates if configured.

### O10.
GCS bucket with public access prevention enforced and `allUsers` binding added.
**Result:** binding rejected/ineffective; objects remain private.

### O11.
Cloud SQL HA zone failure.
**Result:** automatic failover to standby in another zone (about a minute); same IP, connections reset.

### O12.
VPC-SC perimeter blocks BigQuery export to a bucket in an external project.
**Result:** request denied even with valid IAM; perimeter violation logged.

# ⚠️ Part 16: Common Mistakes

1. **Service account keys** in repos/CI instead of WIF/impersonation.
2. **Basic roles (Editor/Owner)** granted widely.
3. **Single project for everything** (prod/dev mixed).
4. **Public buckets/external IPs** without need.
5. **No Org Policies** or VPC-SC for sensitive data.
6. **Zonal-only deployments** and no failure testing.
7. **Unpartitioned BigQuery tables** and `SELECT *` scans.
8. **Monotonic keys** in Spanner/Bigtable causing hotspots.
9. **Forgetting Cloud NAT/Private Google Access** for private VMs.
10. **Allowing health-check ranges** missing in firewall rules.
11. **Pub/Sub consumers non-idempotent** and without DLQ.
12. **Ignoring quotas** before launches.
13. **Manual console changes** without Terraform/IaC.
14. **Log ingestion cost** from verbose logs and data access logs.
15. **Cloud Run cold-start-sensitive APIs** without min instances.
16. **Not using labels/budgets** for cost visibility.
17. **Over-permissive firewall rules** (0.0.0.0/0 on admin ports).
18. **Skipping Binary Authorization/vulnerability scanning.**
19. **Under-sized GKE secondary IP ranges.**
20. **No backups/DR drills** for Cloud SQL/Spanner/BigQuery.
21. **Using legacy services** (Container Registry, Deployment Manager) for new builds.
22. **Treating IAM conditions as a substitute for network controls.**

### Architecture checklist
Regional/multi-zone compute • global LB + CDN/Armor • private IPs + NAT + PGA/PSC • HA databases + backups • Pub/Sub decoupling • keyless auth • CMEK/Secret Manager • Org Policy + VPC-SC • IaC + CI/CD with WIF • SLO monitoring • DR plan • labels/budgets.
